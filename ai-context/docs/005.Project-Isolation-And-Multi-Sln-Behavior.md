## 第 1 部分：工程隔离

### 1.1 三层现状

| 层 | 是否支持按 repo 过滤 | 来源 |
| :--- | :--- | :--- |
| 底层 `code_finder.who_calls_function(name, path, repo_path)` | ✅ 第 3 个参数 | `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/code_finder.py:522` |
| 底层 `code_finder.analyze_code_relationships(query_type, target, context, repo_path, depth)` | ✅ 第 4 个参数 | `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/code_finder.py:1178` |
| MCP 工具 `analyze_code_relationships` | ✅ inputSchema 暴露 `repo_path` 给 LLM | `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tool_definitions.py:48` |
| **CLI `cgc analyze callers/calls/...`** | **❌ 没暴露 `--repo` 标志** | `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/main.py:1884-1907` |

**结论**：能力齐全，CLI 没暴露。MCP 在 `repo_path` 参数被 LLM 实际带上时是隔离的；CLI 默认全 DB 扫。

### 1.2 CLI 实际能用的隔离手段

`cgc analyze callers` 只支持两个相关 flag：

| Flag | 作用 | 限制 |
| :--- | :--- | :--- |
| `--file <path>` | 限定**目标函数定义**所在文件 | 不限制 caller，多 repo 同名定义会全报 |
| `--context <name>` | 切到不同的 KuzuDB（每个 context 是独立 DB） | 需要事先建 context 并各自 index |

`--context` 是真隔离（**两个完全分开的 DB**），但前期要规划好。`--file` 不是工程隔离，是单文件过滤。

### 1.3 没有 `--repo` 时的 4 种规避

#### 方法 A：直接用 `cgc query` 写 Cypher

```powershell
cgc query "MATCH (caller:Function)-[:CALLS]->(target:Function {name:'DoPerset'}) WHERE caller.path STARTS WITH 'F:\\codingnet\\FSAutoBuildTool' RETURN caller.name AS caller, caller.path AS path, caller.line_number AS line"
```

注意 Windows 路径里 `\` 在 Cypher 字符串里要写双反斜杠 `\\`。

#### 方法 B：MCP 调用时让 LLM 传 `repo_path`

让 Claude Code 的 LLM 主动加 `repo_path`：

```json
{
  "name": "analyze_code_relationships",
  "arguments": {
    "query_type": "find_callers",
    "target": "DoPerset",
    "repo_path": "F:\\codingnet\\FSAutoBuildTool"
  }
}
```

提示 LLM 总是带 `repo_path` 的两种办法：
- 在工程级 `.mcp.json` 的 `env` 里多加一个隐藏字段（不 work，CGC 不读 env 提示 LLM）
- **改 `tool_definitions.py:39` 的 description**，加一句「always pass repo_path when in a project context」（work，能进入 LLM 的工具描述）。

#### 方法 C：用 `cgc context` 给每个 repo 独立 DB

CGC 有 "context" 概念，每个 repo 可以有自己的 `.codegraphcontext/` 子目录持自己的 KuzuDB：

```powershell
# 看现在有几个 repo 在共享一个 DB
cgc list

# 进入工程目录，触发本地 context
Push-Location F:\codingnet\FSAutoBuildTool
cgc index .                   # 在本目录建 .codegraphcontext/
Pop-Location

# 查询时 cgc 会自动用本目录的 context；或显式指定：
cgc analyze callers DoPerset --context F:\codingnet\FSAutoBuildTool
```

每个工程一份 DB → 天生隔离。代价：磁盘空间多占一份；切工程时要重建索引。

#### 方法 D：CLI 补 `--repo` 标志（5 行改动，长期方案）

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/main.py:1885-1907` 加：

```python

    visual: bool = typer.Option(False, "--visual", "--viz", "-V", help="..."),
    context: Optional[str] = typer.Option(None, "--context", "-c", help="..."),

    ...
    results = code_finder.who_calls_function(function, file, repo_path=repo)  # ← 透传

`who_calls_function` 已经支持第 3 个参数 `repo_path`，纯透传零风险。`calls`/`callees`/`chain`/`tree` 等命令同理。这是个值得提 PR 的小改动。

## 第 2 部分：多 `.sln` / `.csproj` 行为

### 2.1 真实代码：`_find_csharp_project()`

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:357-365
@staticmethod
def _find_csharp_project(project_path: Path) -> Optional[Path]:
    """Find the first .sln or .csproj file for scip-dotnet."""
    for sln in project_path.glob("*.sln"):
        return sln                              # ← 顶层任意 .sln，第一个就 return
    for csproj in project_path.rglob("*.csproj"):
        if not file_path_has_ignore_dir_segment(csproj, project_path):
            return csproj                       # ← 没 .sln 才退化到任意 .csproj
    return None
```

逻辑：

1. **优先 `.sln`**：`project_path.glob("*.sln")` 仅扫描**顶层**（不递归）。Python `glob` 的迭代顺序由文件系统决定（Windows 上**通常**字母升序，但**没保证**）。**取第一个**直接返回。
2. **退化到 `.csproj`**：找不到 `.sln` 才递归扫 `.csproj`，跳过 `IGNORE_DIRS` 里的目录。同样取第一个。
3. **都找不到**：返回 None，`_build_command` 走「不指定项目」分支：`scip-dotnet index --output ...` ——结果通常是失败或空。

`IGNORE_DIRS` 默认值（`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/config_manager.py:48`）：

```
node_modules, venv, .venv, env, .env, dist, build,
target, out, .git, .idea, .vscode, __pycache__
```

注意：**不含** `obj`、`bin`、`packages`、`TestResults`——`.csproj` 的搜索会扫进 `obj/` 下的临时 csproj！可以通过 `cgc config set IGNORE_DIRS "...,obj,bin"` 覆盖。

### 2.2 各种工程结构下的实际表现

#### 场景 A：根目录 1 个 `.sln`（最常见）

```
FSAutoBuildTool/
├── FSAutoBuildTool.sln          ← 取这个
├── Program.cs
└── ...
```

`scip-dotnet` 用这个 .sln 跑。**没问题**，FSAutoBuildTool 就是这种。

#### 场景 B：根目录多个 `.sln`

```
MyMonorepo/
├── MainApp.sln                  ← 取哪个不可控（Windows 上一般是字母最靠前的）
├── Tests.sln
└── Tools.sln
```

**只索引一个 .sln**。Tests / Tools 里的项目会丢。Python 的 `glob` 文档对返回顺序的描述是 "in arbitrary order"，但 Windows NTFS 在大多数情况下表现为字母升序——**别依赖这点**。

> **解决办法**：
> 1. **拆分子目录索引**：每个 .sln 放进自己的子目录
>    ```powershell
>    cgc index F:\repos\MyMonorepo\src     # 这里只放 MainApp.sln
>    cgc index F:\repos\MyMonorepo\tests   # 这里只放 Tests.sln
>    ```
> 2. **临时挪走多余的 .sln**：
>    ```powershell
>    Move-Item Tests.sln Tests.sln.bak
>    cgc index F:\repos\MyMonorepo --force
>    Move-Item Tests.sln.bak Tests.sln
>    ```
> 3. **改名让你想要的字母最靠前**：`Aaa-MainApp.sln`（hacky，不推荐）。

#### 场景 C：没 `.sln`，根目录有 `.csproj`

```
SimpleProject/
├── SimpleProject.csproj         ← 取这个
└── Program.cs
```

OK，`scip-dotnet` 用这个 .csproj 跑。

#### 场景 D：没 `.sln`，多个 `.csproj` 散在子目录

```
MyMonorepo/
├── src/
│   ├── App/App.csproj           ← 可能取这个
│   └── Lib/Lib.csproj
└── tests/
    └── Tests/Tests.csproj
```

**只索引第一个找到的 .csproj**（`rglob` 返回顺序同样 filesystem 决定，通常深度优先字母升序）。其他 `.csproj` 全丢。

> **解决办法**：**强烈建议补一个 .sln** 引用所有 .csproj：
> ```powershell
> Push-Location F:\repos\MyMonorepo
> dotnet new sln -n MyMonorepo
> Get-ChildItem -Recurse -Filter *.csproj | ForEach-Object { dotnet sln add $_.FullName }
> Pop-Location
> cgc index F:\repos\MyMonorepo --force
> ```
> `scip-dotnet` 拿到 .sln 会一次跑完所有项目，CGC 也只看一个 SCIP 输出，干净。

#### 场景 E：`.csproj` 在 `obj/` 临时目录里

```
MyProject/
├── MyProject.csproj             ← 真的目标
└── obj/
    └── Debug/
        └── tmp.csproj           ← 不要选这个
```

**默认会被选中**（因为 `IGNORE_DIRS` 默认没 `obj`）。表现：scip-dotnet 跑临时 csproj，索引完全错。

> **解决办法**：
> ```powershell
> cgc config set IGNORE_DIRS "node_modules,venv,.venv,env,.env,dist,build,target,out,.git,.idea,.vscode,__pycache__,obj,bin"
> cgc index F:\repos\MyProject --force
> ```
> 也可以用 `.cgcignore` 文件：`@e:/claude-hub/CodeGraphContext/.cgcignore` 是仓库自带的示例。

### 2.3 怎么判断 `cgc index` 实际选了哪个

```
... Running local SCIP indexer: scip-dotnet index <THIS_PATH> --working-directory <DIR> --output <TMP>\index.scip
```

`<THIS_PATH>` 就是被选中的 `.sln` 或 `.csproj` 绝对路径。**遇到结果不对先看这一行**。

### 2.4 工程组织建议

避免歧义：

1. **每个根目录恰好一个 .sln**（推荐）。`scip-dotnet` 走 .sln 是最准的——Roslyn 一次加载所有项目，跨项目引用解析齐。
2. **多 .sln 必须**：每个 .sln 各占一个子目录，分别 `cgc index` 进不同 context。
3. **没 .sln**：建一个 .sln 把所有 .csproj 拉进来。`dotnet new sln + dotnet sln add` 几行就行。
4. **千万别**让 `cgc index <root>` 落到只能找单个 .csproj 的状态——会丢一大半项目。

## 速查表

### 工程隔离

| 我用 | 隔离方式 |
| :--- | :--- |
| `cgc query` | Cypher 加 `WHERE node.path STARTS WITH '<repo>'` |
| `cgc analyze ...`（CLI） | 暂无 `--repo`；用 `--context` 切独立 DB |
| Claude Code（MCP） | LLM 在调用工具时带 `repo_path` 参数 |
| `cgc context` | 每个 repo 独立 KuzuDB（最干净） |

### 多 .sln / .csproj

| 工程结构 | cgc 行为 | 推荐做法 |
| :--- | :--- | :--- |
| 1 个 .sln | 完美 | 维持现状 |
| 多个 .sln | 只取第一个（顺序不保证） | 拆子目录或临时挪走 |
| 多个 .csproj 无 .sln | 只取第一个递归到的 .csproj | 加一个 .sln 引用全部 |
| `obj/`/`bin/` 内有 .csproj | 默认会扫到 | 把 `obj,bin` 加进 `IGNORE_DIRS` |
