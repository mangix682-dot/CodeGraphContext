## 0. TL;DR

| 问题 | 答案 |
| :--- | :--- |
| 写 `.mcp.json`（工程级，**带点**）吗？ | **不写**。`cgc mcp setup` 完全不管这个文件 |
| 写 `mcp.json`（**不带点**）吗？ | **写**。写在**当前工作目录** `<cwd>/mcp.json` |
| 写用户级 IDE 配置吗？ | **写**。如选 Claude code → 改 `%USERPROFILE%\.claude.json` |
| 把 system prompt 写进配置文件吗？ | **不写**。system prompt 不在任何 JSON 配置里 |
| 那 system prompt 在哪？ | 硬编码在 `prompts.py:9`，运行时通过 `initialize` 响应的 `serverInfo.systemPrompt` 字段下发 |
| Host 收到后会照做吗？ | **看 host**。这个字段不在 MCP 标准里，是 CGC 自加的非标字段 |

## 1. 完整执行流程

入口在 `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/main.py:105`：

```python
@mcp_app.command("setup")
def mcp_setup():
    configure_mcp_client()
```

`configure_mcp_client()` 在 `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/setup_wizard.py:481`，做 5 件事：

### 步骤 1：从 `~/.codegraphcontext/.env` 读全部当前配置

包括 Neo4j 凭据 + SCIP_INDEXER + IGNORE_DIRS + DEFAULT_DATABASE 等等，全部塞进 `env_vars` 字典。

### 步骤 2：决定 `command` 与 `args`

```
shutil.which("cgc")    → "C:\\Users\\<you>\\.local\\bin\\cgc.exe"  ✓ 优先
shutil.which("pipx")   → 退化到 pipx run codegraphcontext mcp start
sys.executable         → 兜底用 python -m codegraphcontext mcp start
```

### 步骤 3：拼出 `mcp_config` 字典

```json
{
  "mcpServers": {
    "CodeGraphContext": {
      "command": "C:\\Users\\<you>\\.local\\bin\\cgc.exe",
      "args": ["mcp", "start"],
      "env": {
        "NEO4J_URI": "...",
        "SCIP_INDEXER": "true",
        "SCIP_LANGUAGES": "csharp",
        "DEFAULT_DATABASE": "kuzudb"
      },
      "tools": {
        "alwaysAllow": ["add_code_to_graph", "...", 15 个],
        "disabledTools": [],
        "disabled": false
      },
      "disabled": false,
      "alwaysAllow": []
    }
  }
}
```

### 步骤 4：写到 `<cwd>/mcp.json`

```python
mcp_file = Path.cwd() / "mcp.json"             # ← 注意：cwd，不是工程根
json.dump(mcp_config, f, indent=2)
```

文件名是 `mcp.json`（**不带点**）。位置是**你执行 `cgc mcp setup` 时所在目录**——如果你是在 `C:\Users\mangix` 跑的，文件就写到 `C:\Users\mangix\mcp.json`。

### 步骤 5：`_configure_ide(mcp_config)` 自动改 IDE 配置

- 弹两个交互问题：
  1. `Automatically configure your IDE/CLI? Y/n`
  2. 列出 16 个 IDE 让你选
- 按选项查到对应 IDE 的**用户级**配置文件路径
- 读、合并 `mcp_config["mcpServers"]`、写回

## 3. `mcp.json` vs `.mcp.json` 是两个不同的东西

| 文件 | 谁写 | 谁读 | 用途 |
| :--- | :--- | :--- | :--- |
| `<cwd>/mcp.json`（**不带点**） | `cgc mcp setup` 总会写一份 | **CGC 自己** 在 `cgc mcp start` 启动时回读，**用来禁用工具** | 你拿来当模板复制；CGC 用来过滤工具 |
| `<project>/.mcp.json`（**带点**） | 你**手写** 或 团队入 git | **Claude Code** 启动时扫到，spawn cgc 子进程 | Claude Code 工程级 MCP 服务器声明 |
| `~/.claude.json` | `cgc mcp setup` 选 Claude code 时写 | **Claude Code** 启动时读 | Claude Code 用户级 MCP 服务器声明（全局） |

### 3.1 `<cwd>/mcp.json` 怎么被 CGC 回读

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/server.py:218
def _load_disabled_tools(self) -> Set[str]:
    mcp_file = self.cwd / "mcp.json"     # ← cwd 下的 mcp.json
    if not mcp_file.exists():
        return set()
    ...
    disabled_tools = (
        mcp_config.get("mcpServers", {})
        .get("CodeGraphContext", {})
        .get("tools", {})
        .get("disabledTools", [])
    )
```

也就是说 `mcp.json` 里 `tools.disabledTools` **不是 Claude Code 解释的**，是 **CGC 自己解释的**——服务器启动时按这个清单过滤 `tools/list` 响应里不上报的工具。

### 3.2 `<cwd>` 是哪？

是「**Claude Code 启动 cgc 子进程时的工作目录**」，不是工程根。Claude Code 通常用工程根做 cwd，但**不保证**。如果想稳定生效（比如想给 FSAutoBuildTool 工程禁用某些工具），把 `mcp.json` 放工程根：`F:\codingnet\FSAutoBuildTool\mcp.json`。

## 4. system prompt：在哪？怎么注入？

### 4.1 system prompt 写死在 Python 源码里

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/prompts.py:9
LLM_SYSTEM_PROMPT = """# AI Pair Programmer Instructions

## 1. Your Role and Goal
...
"""
```

`cgc mcp setup` **不会**把这段写进任何 JSON 文件。这是**编译期常量**——你想改它必须改 Python 文件。

### 4.2 它通过 `initialize` 响应注入

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/server.py:591-602
if method == 'initialize':
    response = {
        "jsonrpc": "2.0", "id": request_id,
        "result": {
            "protocolVersion": "2025-03-26",
            "serverInfo": {
                "name": "CodeGraphContext",
                "version": self._get_version(),
                "systemPrompt": LLM_SYSTEM_PROMPT      # ← 这里
            },
            "capabilities": {"tools": {"listTools": True}}
        }
    }
```

握手时 cgc 把整段 prompt 塞到 `serverInfo.systemPrompt` 字段，发回给 host。

### 4.3 host 会不会读这个字段？取决于 host

`serverInfo.systemPrompt` **不是 MCP 标准协议字段**——MCP spec 只规定了 `serverInfo.name` 和 `serverInfo.version`，CGC 加了个非标的 `systemPrompt`。结果：

| Host | 行为 |
| :--- | :--- |
| Claude Desktop（旧版） | 会拼到对话的 system prompt |
| Cursor | 部分版本会读 |
| **Claude Code** | **看版本**——新版倾向忽略非标字段。要让 LLM 真按这套指令工作，更稳是放进 `CLAUDE.md`（工程级）或 `~/.claude/CLAUDE.md`（用户级） |
| 其他 host | 大多数无视 |

如果 Claude Code 没按 `prompts.py` 的指导走，**把那段 prompt 复制一份到 `F:\codingnet\FSAutoBuildTool\CLAUDE.md`** 是更稳的做法。

### 4.4 改 system prompt 的正确方法

1. 编辑 `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/prompts.py:9` 的 `LLM_SYSTEM_PROMPT` 字符串。
2. 完全退出 Claude Code（任务栏右键 Quit），重启。Claude Code 会重新 spawn `cgc mcp start`，重新拿到新 prompt。
3. 仅 `cgc` 是 editable 安装时这一步立即生效（你这台机器是的）；如果是 `pipx install codegraphcontext`（非 editable），改完要 `pipx reinstall codegraphcontext`。

> 不要在 `mcp.json` 或 `.claude.json` 里加 `systemPrompt` 字段——既不会被 cgc 读到（cgc 只读 `tools.disabledTools`），也不会被大多数 host 读到。

## 5. `tools.alwaysAllow` 和 `tools.disabledTools` 实际作用

### 5.1 `tools.alwaysAllow`（host 侧自动批准）

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/setup_wizard.py:553-561` 默认硬编码 15 个：

```json
"alwaysAllow": [
  "add_code_to_graph", "add_package_to_graph",
  "check_job_status", "list_jobs", "find_code",
  "analyze_code_relationships", "watch_directory",
  "find_dead_code", "execute_cypher_query",
  "calculate_cyclomatic_complexity", "find_most_complex_functions",
  "list_indexed_repositories", "delete_repository",
  "list_watched_paths", "unwatch_directory", "visualize_graph_query"
]
```

这是**给 host 用的提示**——「这 15 个工具调用时不必每次问用户允许」。**不同 host 解释不一致**：Cline 完全支持；Claude Code 自己有 approval 机制，多半忽略。

CGC server 端 **不消费** `alwaysAllow`。

### 5.2 `tools.disabledTools`（CGC 侧过滤）

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/server.py:191
self.tools = {
    name: definition
    for name, definition in TOOLS.items()
    if name not in self.disabled_tools         # ← 从 mcp.json 加载
}
```

CGC 在 `tools/list` 响应里**不报**被禁用的工具，host 自然就看不到、调不了。

> 想给某个工程禁用「写操作」工具，把这段放工程根的 `mcp.json`（**不带点**！）：
>
> ```json
> {
>   "mcpServers": {
>     "CodeGraphContext": {
>       "tools": {
>         "disabledTools": [
>           "delete_repository",
>           "watch_directory",
>           "unwatch_directory",
>           "add_code_to_graph",
>           "add_package_to_graph"
>         ]
>       }
>     }
>   }
> }
> ```

## 6. 跟你当前用的工程级 `.mcp.json` 的关系

你之前手写的 `@F:/codingnet/FSAutoBuildTool/.mcp.json`（带点）跟 `cgc mcp setup` **完全不冲突**：

| 文件 | 现状 | 作用 |
| :--- | :--- | :--- |
| `F:\codingnet\FSAutoBuildTool\.mcp.json` | 你手写、Claude Code 工程级 | 告诉 Claude Code「在这工程下启动 CodeGraphContext MCP」 |
| `~/.claude.json` 的 `mcpServers` | 没动过（你没跑 `cgc mcp setup`） | 全局 MCP 列表（你这里是空的或没 CGC） |
| `F:\codingnet\FSAutoBuildTool\mcp.json` | **不存在** | 如果你想给该工程禁用某些工具，可以新建 |

如果你现在跑一次 `cgc mcp setup` 选 Claude code：
- 会**新增**一份 CGC 配置到 `~/.claude.json`（用户级、全局生效）
- 会**额外**在你跑命令时所在目录写一份 `mcp.json` 模板
- **不会**碰 `F:\codingnet\FSAutoBuildTool\.mcp.json`

结果就是 Claude Code 在 FSAutoBuildTool 里**会有两份**同名 MCP server 定义：一份来自工程级 `.mcp.json`（你手写），一份来自用户级 `~/.claude.json`（向导写）。Claude Code 会按优先级合并/去重，但一般会让 LLM 看到两份重复的工具。**不建议两个都开**。

## 7. 三种"我想让 Claude Code 用 CGC"的推荐组合

| 场景 | 用什么 | 跑 `cgc mcp setup` 吗？ |
| :--- | :--- | :--- |
| 全局，所有工程都能用 | `cgc mcp setup` 一次写 `~/.claude.json` | ✅ |
| 只给 FSAutoBuildTool 用 | 手写 `F:\codingnet\FSAutoBuildTool\.mcp.json`（你现在的方式） | ❌ 不要跑，避免重复 |
| 只给 FSAutoBuildTool + 想禁用部分工具 | 手写 `.mcp.json` + 工程根再放 `mcp.json`（disabledTools） | ❌ |
