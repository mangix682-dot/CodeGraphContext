# 009. RoslynGraphContext：百万行纯 C# 游戏项目的代码图谱系统架构

> **目标**：借鉴 CGC 的"代码→图数据库→AI 查询"架构思想，专精 C#，用 **Roslyn 原生语义分析** 替代 Tree-sitter + SCIP，为百万行 C# 游戏项目构建一个高精度、高性能的代码图谱系统。
>
> **技术栈**：C# / .NET 8+ / Roslyn (`Microsoft.CodeAnalysis`) / 图数据库 / MCP Server

---

## 0. 核心设计原则

| # | 原则 | 借鉴自 CGC | Roslyn 专精改进 |
| :--- | :--- | :--- | :--- |
| 1 | **编译一次，查询无限次** | ✅ 离线索引到图数据库 | Roslyn 编译 → 提取全部语义 → 写入图，之后不再需要 Roslyn |
| 2 | **图原生查询** | ✅ Cypher 多跳遍历 | 同，但图 Schema 更丰富（泛型、重载、隐式转换） |
| 3 | **MCP 接口暴露给 AI** | ✅ JSON-RPC over stdio | 同，C# 实现的 MCP Server |
| 4 | **增量更新** | ✅ 文件级 watch | Roslyn 增量编译 + 差量图更新 |
| 5 | **单语言专精** | ❌ CGC 要支持 20 种语言 | 去掉所有多语言抽象，所有代码路径为 C# 优化 |

## 2. 模块设计

### 2.1 RoslynAnalyzer — 语义提取引擎（CGC 中 Tree-sitter + SCIP 的合体）

这是与 CGC 最大的差异点。CGC 用 Tree-sitter（语法层）+ SCIP（语义层）两套系统拼接，我们直接用 Roslyn 一步到位。

```csharp
// 伪代码：核心提取逻辑
public class RoslynAnalyzer
{
    private MSBuildWorkspace _workspace;
    private Solution _solution;

    public async Task<GraphData> AnalyzeSolution(string slnPath)
    {
        _solution = await _workspace.OpenSolutionAsync(slnPath);
        var graphData = new GraphData();

        foreach (var project in _solution.Projects)
        {
            var compilation = await project.GetCompilationAsync();
            foreach (var syntaxTree in compilation.SyntaxTrees)
            {
                var semanticModel = compilation.GetSemanticModel(syntaxTree);
                var root = await syntaxTree.GetRootAsync();

                // 一次遍历，同时提取所有信息
                var walker = new FullSemanticWalker(semanticModel, graphData);
                walker.Visit(root);
            }
        }
        return graphData;
    }
}
```

**FullSemanticWalker 提取的内容**（CGC 用 Tree-sitter + SCIP 分两轮的，我们一轮全搞定）：

| 提取项 | Roslyn API | CGC 对应 | 精度提升 |
| :--- | :--- | :--- | :--- |
| 函数定义 + 源码 + 复杂度 | `MethodDeclarationSyntax` + `GetText()` + 自行计算 | Tree-sitter 函数解析 + 补充 source/complexity | 一步完成，无需两轮 |
| 调用关系 | `InvocationExpressionSyntax` → `GetSymbolInfo()` → 精确到重载 | SCIP CALLS 边 | **含重载决议、泛型实例化** |
| 继承/实现 | `INamedTypeSymbol.BaseType` / `.Interfaces` | SCIP `is_implementation` | **含泛型基类参数** |
| Attributes | `ISymbol.GetAttributes()` | Tree-sitter 补充 decorators | **含 attribute 参数值** |
| 泛型参数 | `INamedTypeSymbol.TypeArguments` | ❌ CGC 丢失 | **全新能力** |
| 隐式转换 | `Conversion` from `GetConversion()` | ❌ CGC 无法感知 | **全新能力** |
| 扩展方法绑定 | `IMethodSymbol.ReducedFrom` | ❌ SCIP 部分支持 | **精确到原始静态方法** |
| Partial class 合并 | `INamedTypeSymbol.Locations` 多个 | ❌ CGC 各文件独立 | **统一视图** |
| 运算符重载 | `IMethodSymbol` (operator) | ❌ CGC 不追踪 | **全新能力** |
| Nullable 状态 | `NullableFlowState` | ❌ CGC 无 | **全新能力** |
| Source Generator 产物 | `compilation.SyntaxTrees` 含 generated | ❌ CGC 忽略 obj/ | **全新能力** |
| using/namespace | `UsingDirectiveSyntax` | Tree-sitter 补充 | 同精度 |
| 字段/属性 + 完整类型 | `IFieldSymbol.Type` / `IPropertySymbol.Type` | SCIP 部分 + Tree-sitter 补 | **含泛型参数的完整类型名** |

### 2.2 GraphBuilder — 索引编排器

```
┌─────────────────────────────────────────────────────────────┐
│                    GraphBuilder 流程                          │
│                                                             │
│  1. 加载 Solution                                            │
│     └── MSBuildWorkspace.OpenSolutionAsync(sln)              │
│         └── 自动处理 multi-sln：扫描根目录，合并多个 Solution  │
│                                                             │
│  2. 并行编译各 Project                                       │
│     └── Parallel.ForEachAsync(projects, GetCompilationAsync) │
│         └── 百万行约 60-90s（与 dotnet build 同量级）         │
│                                                             │
│  3. 语义遍历                                                 │
│     └── 每个 SyntaxTree 走一遍 FullSemanticWalker            │
│         └── 产出：nodes[] + edges[] 的批量数据                │
│                                                             │
│  4. 批量写入图数据库                                          │
│     └── GraphWriter.BulkInsert(nodes, edges)                │
│         └── 使用事务批量 MERGE，万级节点/s                    │
│                                                             │
│  5. 后处理                                                   │
│     └── 构建 Directory 层级节点                              │
│     └── 计算模块耦合度统计                                    │
│     └── 标记入口点（Main / MonoBehaviour 生命周期方法）        │
└─────────────────────────────────────────────────────────────┘
```

**与 CGC 的关键区别**：

| 环节 | CGC | RoslynGraphContext |
| :--- | :--- | :--- |
| 编译 | `scip-dotnet` 外部进程调用 Roslyn，产出 protobuf | 内嵌 Roslyn，直接访问 `SemanticModel` |
| 数据传递 | protobuf 序列化 → Python 反序列化 → Cypher 写入 | 内存中直接构建 node/edge 对象 → 批量写入 |
| 信息丢失 | SCIP 协议丢弃泛型参数、属性参数、源码、复杂度 | **零丢失**，Roslyn 有什么就提取什么 |
| 补充轮 | 需要 Tree-sitter 补源码/复杂度/属性 | 不需要任何补充轮 |

### 2.3 图 Schema — 比 CGC 更丰富

| `Interface` | name, path, line, endLine, source, genericParameters | interface |

### 2.5 MCP Server — AI 接口

CGC 用 Python 实现 21 个 MCP 工具。我们用 C# 实现，工具数更多且专精。

**关键架构决策**：因为底层就是 Roslyn，我们不仅能做 CGC 的「离线图谱查询」，还能保留一个 **轻量 Roslyn Workspace** 提供 CGC 永远做不到的实时语义能力（重构、诊断、类型推断）。这是纯 Roslyn 方案相比 CGC 的根本优势。

### 2.6 工具分类：预计算 vs 实时 Roslyn vs 两者皆可

> **设计原则**：40GB 数据库上限内，能预计算的都预计算。只有「必须感知当前编辑状态」或「修改代码」的操作才走实时 Roslyn。

#### A 类：纯预计算（走图数据库，< 50ms，无需 Roslyn 常驻）

这些工具的数据在索引时已经**完整写入图数据库**，查询时只需 Cypher 遍历。

| 工具 | 预计算存储内容 | DB 增量估算（百万行） |
| :--- | :--- | :--- |
| `find_symbol` | 所有符号的 name/fullName 索引 | ~5 MB（索引） |
| `find_by_attribute` | Attribute 存为节点属性 `attributes: ["Serializable", ...]` | ~3 MB |
| `find_by_content` | 方法/类的 `source` 字段全文索引 | **~600 MB**（全部源码） |
| `find_by_type` | 节点 label（Class/Method/Field 等） | 0（schema 自带） |
| `who_calls` | CALLS 边（精确到重载） | ~30 MB（~200k 边） |
| `what_calls` | 同上（反向遍历） | 0（同一组边） |
| `find_call_chain` | 图多跳遍历 | 0（运行时计算路径） |
| `find_all_callers` | 图传递闭包 | 0（运行时计算） |
| `impact_analysis` | 图反向传递遍历 | 0（运行时计算） |
| `find_entry_to_target` | 入口点标记 + 图路径搜索 | ~0.1 MB（入口标记） |
| `class_hierarchy` | INHERITS + IMPLEMENTS 边 | ~5 MB（~20k 边） |
| `find_overrides` | OVERRIDES 边 | ~8 MB（~50k 边） |
| `find_implementations` | IMPLEMENTS 边 | ~3 MB（含上面） |
| `find_partial_parts` | 同一 Class 节点多个 `locations[]` | ~1 MB |
| `find_extension_methods` | 扩展方法节点标记 `isExtension=true` + `extendedType` 属性 | ~2 MB |
| `find_dead_code` | 图查询：`WHERE NOT ()-[:CALLS]->(f)` | 0（运行时计算） |
| `complexity_ranking` | 节点属性 `cyclomaticComplexity` | ~0.5 MB |
| `namespace_coupling` | CALLS 边按命名空间聚合 | 0（运行时聚合） |
| `find_god_classes` | 节点属性 `memberCount` / 运行时 count | ~0.3 MB |
| `find_long_methods` | 节点属性 `lineCount` | ~0.3 MB |
| `execute_cypher` | 任意图查询 | 0 |
| **A 类 DB 总计** | | **~660 MB** |

#### B 类：两者皆可（预计算 + 可选实时刷新）

这些工具可以在索引时预计算并存入数据库，但数据可能随编辑变化。策略是：**索引时写入快照，`watch` 触发增量刷新**。

| 工具 | 预计算方案 | 实时 Roslyn 方案 | 推荐 | DB 增量 |
| :--- | :--- | :--- | :--- | :--- |
| `find_generic_usages` | 索引时遇到 `new List<Bullet>()` 即存 `USES_GENERIC(Method→Class, typeArgs:"Bullet")` 边 | `FindReferences` + 检查 `TypeArgumentList` | **预计算** ✅ — 泛型实例化在代码库中相对固定 | ~20 MB（~100k 泛型使用点） |
| `get_diagnostics` | 索引时执行 `GetDiagnostics()` 存为 Diagnostic 节点（file, line, severity, message） | 每次查询实时跑 `GetDiagnostics()` | **预计算快照 + watch 刷新** ✅ — 99% 场景下快照够用；AI 看到的诊断不需要毫秒级实时 | ~15 MB（~50k 诊断记录） |
| `get_nullable_warnings` | 同上（筛选 `CS8600`-`CS8655` 系列） | 实时 Nullable 分析 | **预计算** ✅ — Nullable 警告只在代码变更时变化，watch 会刷新 | 含在上面 |
| `get_analyzer_results` | 索引时跑自定义 Analyzer 存结果 | 每次实时跑 Analyzer | **预计算** ✅ — Analyzer 结果较稳定，watch 刷新足够 | ~10 MB |
| `resolve_type_at` (声明级) | 字段/属性/参数/返回值的类型已存为节点属性 `type: "List<Bullet>"` | `GetSymbolInfo()` at position | **预计算** ✅ — 覆盖 90% 场景（AI 通常问的是声明级类型） | 已含在节点属性中 |
| `get_overload_candidates` | 对每个 CALLS 边，额外存 `allOverloads: ["Attack(int)", "Attack(float)", "Attack(Vector3)"]` | `GetSymbolInfo().CandidateSymbols` | **预计算** ✅ — 重载列表在代码不变时固定 | ~40 MB（每条 CALLS 边多存候选列表） |
| **B 类 DB 总计** | | | | **~85 MB** |

#### C 类：必须实时 Roslyn（不可预计算，或预计算无意义）

| 工具 | 为什么不能预计算 | 实时开销 |
| :--- | :--- | :--- |
| `rename_symbol` | **修改代码**——需要生成新的 SyntaxTree 并写回文件 | 1–5s（跨文件重命名） |
| `extract_method` | **修改代码**——需要分析选中代码块的数据流，生成新方法 | 2–5s |

| `move_type_to_file` | **修改代码**——需要移动语法节点到新文件 + 修复 using | 1–3s |

```csharp
public class SmartQueryRouter
{
    private readonly GraphQuerier _graph;
    private readonly Lazy<RoslynWorkspace> _roslyn;

    public async Task<object> Route(string tool, Dictionary<string, object> args)
    {
        // A 类：永远走图
        if (IsGraphOnlyTool(tool))
            return await _graph.Execute(tool, args);

        // B 类：优先走图，快照过期时 fallback
        if (IsHybridTool(tool))
        {
            var result = await _graph.Execute(tool, args);
            if (result.IsStale && _roslyn.IsValueCreated)
                return await _roslyn.Value.Execute(tool, args);
            return result;
        }

        // C 类：必须走 Roslyn
        return await _roslyn.Value.Execute(tool, args);
    }
}
```

## 5. 关键实现细节

### 5.1 FullSemanticWalker — 一轮遍历提取所有语义

CGC 的问题是要**两轮**（SCIP 一轮提关系 → Tree-sitter 一轮补源码/复杂度），我们一轮搞定：

```csharp
public class FullSemanticWalker : CSharpSyntaxWalker
{
    private readonly SemanticModel _model;
    private readonly GraphData _graph;
    private readonly string _filePath;

    // 一次遍历同时做 5 件事：
    // 1. 提取定义（类/方法/属性/字段）
    // 2. 提取源码文本
    // 3. 计算复杂度
    // 4. 解析调用关系（含重载决议）
    // 5. 解析继承/实现关系

    public override void VisitMethodDeclaration(MethodDeclarationSyntax node)
    {
        var symbol = _model.GetDeclaredSymbol(node);
        if (symbol == null) { base.VisitMethodDeclaration(node); return; }

        // 1. 定义 → MethodNode
        var methodNode = new MethodNode
        {
            Name = symbol.Name,
            FullName = symbol.ToDisplayString(),
            Path = _filePath,
            Line = node.GetLocation().GetLineSpan().StartLinePosition.Line + 1,
            EndLine = node.GetLocation().GetLineSpan().EndLinePosition.Line + 1,
            ReturnType = symbol.ReturnType.ToDisplayString(),
            Parameters = symbol.Parameters.Select(p => $"{p.Type.ToDisplayString()} {p.Name}").ToList(),
            Accessibility = symbol.DeclaredAccessibility.ToString(),
            IsStatic = symbol.IsStatic,
            IsAsync = symbol.IsAsync,
            IsVirtual = symbol.IsVirtual,
            IsOverride = symbol.IsOverride,
            IsAbstract = symbol.IsAbstract,
            // 2. 源码
            Source = node.ToFullString(),
            // 3. 复杂度
            CyclomaticComplexity = ComplexityCalculator.Calculate(node),
            // Attributes
            Attributes = symbol.GetAttributes()
                .Select(a => a.ToString()).ToList(),
        };
        _graph.AddNode(methodNode);

        // 5. override 关系
        if (symbol.IsOverride && symbol.OverriddenMethod != null)
        {
            _graph.AddEdge(new OverridesEdge(methodNode, /*target overridden method*/));
        }

        // 继续遍历方法体内的调用
        base.VisitMethodDeclaration(node);
    }

    public override void VisitInvocationExpression(InvocationExpressionSyntax node)
    {
        // 4. 调用关系 — Roslyn 自动解析重载
        var symbolInfo = _model.GetSymbolInfo(node);
        if (symbolInfo.Symbol is IMethodSymbol callee)
        {
            // 精确到具体重载，包含泛型参数
            _graph.AddEdge(new CallsEdge(
                callerMethod: _currentMethod,
                calleeFullName: callee.OriginalDefinition.ToDisplayString(),
                calleeName: callee.Name,
                line: node.GetLocation().GetLineSpan().StartLinePosition.Line + 1,
                // 扩展方法：记录原始静态方法
                isExtensionMethod: callee.IsExtensionMethod,
                reducedFrom: callee.ReducedFrom?.ToDisplayString(),
            ));
        }
        base.VisitInvocationExpression(node);
    }
}
```

### 5.2 ComplexityCalculator — 圈复杂度

CGC 用 Tree-sitter 数分支节点。我们用 Roslyn SyntaxWalker，精度相同但与主遍历集成：

```csharp
public static class ComplexityCalculator
{
    public static int Calculate(MethodDeclarationSyntax method)
    {
        int complexity = 1; // 基础路径
        foreach (var node in method.DescendantNodes())
        {
            complexity += node switch
            {
                IfStatementSyntax => 1,
                ElseClauseSyntax { Statement: IfStatementSyntax } => 0, // else if 不重复计
                ConditionalExpressionSyntax => 1,    // ?:
                WhileStatementSyntax => 1,
                ForStatementSyntax => 1,
                ForEachStatementSyntax => 1,
                DoStatementSyntax => 1,
                CaseSwitchLabelSyntax => 1,
                CasePatternSwitchLabelSyntax => 1,
                CatchClauseSyntax => 1,
                BinaryExpressionSyntax b when
                    b.IsKind(SyntaxKind.LogicalAndExpression) ||
                    b.IsKind(SyntaxKind.LogicalOrExpression) ||
                    b.IsKind(SyntaxKind.CoalesceExpression) => 1,  // && || ??
                _ => 0,
            };
        }
        return complexity;
    }
}
```

### 5.3 游戏项目专属：Unity / 自研引擎感知

```csharp
public static class GameProjectAwareness
{
    // MonoBehaviour 生命周期方法不应被标记为死代码
    private static readonly HashSet<string> UnityLifecycleMethods = new()
    {
        "Awake", "Start", "Update", "FixedUpdate", "LateUpdate",
        "OnEnable", "OnDisable", "OnDestroy", "OnGUI",
        "OnCollisionEnter", "OnCollisionExit", "OnTriggerEnter", "OnTriggerExit",
        "OnApplicationQuit", "OnApplicationPause",
    };

    // 标记入口点：这些方法被引擎隐式调用，不算死代码
    public static bool IsImplicitlyCalledByEngine(IMethodSymbol method)
    {
        if (UnityLifecycleMethods.Contains(method.Name))
        {
            var containingType = method.ContainingType;
            while (containingType != null)
            {
                if (containingType.Name is "MonoBehaviour" or "ScriptableObject")
                    return true;
                containingType = containingType.BaseType;
            }
        }
        // [RuntimeInitializeOnLoadMethod] 等特性
        if (method.GetAttributes().Any(a =>
            a.AttributeClass?.Name == "RuntimeInitializeOnLoadMethodAttribute"))
            return true;

        return false;
    }
}
```
