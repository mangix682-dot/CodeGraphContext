## 0. TL;DR（一图速懂）

```
┌─────────────────────────────────────────────────────────────────────┐
│ Claude Code (host process)                                          │
│                                                                     │
│  ① 启动时扫 .mcp.json + ~/.claude.json 的 mcpServers 块             │
│  ② 对每个 server: subprocess.Popen(command, args, env)              │
│  ③ 通过 stdin/stdout 发 JSON-RPC: initialize → tools/list           │
│  ④ 把返回的 tools 加前缀 mcp__<serverName>__ 注入 LLM 的工具上下文   │
│                                                                     │
└───────────────────────┬─────────────────────────────────────────────┘
                        │ stdin (JSON line in)
                        │ stdout (JSON line out)
                        ▼
┌─────────────────────────────────────────────────────────────────────┐
│ cgc.exe mcp start (subprocess)                                      │
│                                                                     │
│  src/codegraphcontext/cli/main.py:122  @mcp_app.command("start")    │
│      └─ MCPServer(...).run()                                        │
│         └─ while True: line = stdin.readline()                      │
│            method == 'initialize'   → 返回 protocolVersion + caps   │
│            method == 'tools/list'   → 返回 TOOLS 字典               │
│            method == 'tools/call'   → handle_tool_call(...)         │
│                                       └─ tool_map[name](**args)     │
└─────────────────────────────────────────────────────────────────────┘
```

整个协议就是「**逐行 JSON over stdio**」，没有 socket、没有 HTTP，子进程被 Claude Code 一个一个 spawn。

## 1. 命名：`mcp__CodeGraphContext__analyze_code_relationships` 这串怎么来的

| 段 | 含义 | 来源 |
| :--- | :--- | :--- |
| `mcp__` | 前缀，标识这是 MCP 工具（区别于 Claude Code 内置的 `Read` / `Write` / `Bash` 等） | Claude Code 命名约定 |
| `CodeGraphContext` | server 名 | 你 `.mcp.json` 里 `mcpServers.CodeGraphContext` 这个 key |
| `analyze_code_relationships` | 工具名 | CGC 后端 `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tool_definitions.py:39` 里 TOOLS 字典的 key |

只要你把 `.mcp.json` 里那个 key 改名（比如改成 `cgc`），Claude Code 看到的工具就会变成 `mcp__cgc__analyze_code_relationships`。CGC 源码 0 改动。

## 2. 注入路径：`.mcp.json` → Claude Code 子进程 → tool registration

### 2.1 Claude Code 启动时读哪些文件

按优先级（后者覆盖前者）：

| 作用域 | 文件 | 谁写 |
| :--- | :--- | :--- |
| 用户级 | `%USERPROFILE%\.claude.json` 的 `mcpServers` 字段 | `cgc mcp setup` 向导，或你手动改 |
| 工程级 | `<project>\.mcp.json` | 你手写（首次启动会要求 approve） |
| Local | `<project>\.claude\settings.local.json` | 单人覆盖，不入 git（这里**不放** MCP server 定义） |

你这次走的是**工程级**：`@F:/codingnet/FSAutoBuildTool/.mcp.json`。

### 2.2 一段 mcpServers 配置都说了啥

```json
{
  "mcpServers": {
    "CodeGraphContext": {                          // ← serverName，前缀来源
      "command": "C:\\Users\\<you>\\.local\\bin\\cgc.exe",
      "args": ["mcp", "start"],                    // ← 拼成 cgc.exe mcp start
      "env": {                                     // ← 注入到子进程环境变量
        "SCIP_INDEXER": "true",
        "SCIP_LANGUAGES": "csharp"
      }
    }
  }
}
```

Claude Code 大致做：

```python
proc = subprocess.Popen(
    [command, *args],
    stdin=PIPE, stdout=PIPE, stderr=PIPE,
    env={**os.environ, **config["env"]},          # 合并父进程 env + 配置 env
    text=True,
)
```

`stderr` 会被 Claude Code 捕获给设置面板的 "MCP servers" log；`stdin`/`stdout` 是协议通道。

### 2.3 Claude Code 与 CGC 的握手（4 个 JSON-RPC 消息）

| 序 | 方向 | 方法 | 作用 |
| :--- | :--- | :--- | :--- |
| 1 | Claude Code → cgc | `initialize` | 协议版本协商 |
| 2 | cgc → Claude Code | response | 返回 `protocolVersion`, `serverInfo`, `capabilities` |
| 3 | Claude Code → cgc | `notifications/initialized` | 通知（无响应） |
| 4 | Claude Code → cgc | `tools/list` | 拉工具清单 |
| 5 | cgc → Claude Code | response | 返回 `TOOLS` 字典里全部 entry |

之后 Claude Code 把这 N 个 entry 各加上 `mcp__CodeGraphContext__` 前缀，塞到 LLM 的工具描述里。LLM 看到的就是「我有 27 个工具可以用」。

### 3.3 server 初始化与 tool 映射

```python
# src/codegraphcontext/server.py:187
def _init_tools(self):
    self.disabled_tools = self._load_disabled_tools()
    self.tools = {
        name: definition
        for name, definition in TOOLS.items()
        if name not in self.disabled_tools
    }
```

`tools` 是从 `TOOLS` 字典过滤出来的，去掉了「user 想禁用」的工具（见 §4）。

### 3.4 协议主循环

```python
# src/codegraphcontext/server.py:567
async def run(self):
    print("MCP Server is running. Waiting for requests...", file=sys.stderr, flush=True)
    self.code_watcher.start()
    while True:
        line = await loop.run_in_executor(None, sys.stdin.readline)
        request = json.loads(line.strip())
        method = request.get('method')

        if method == 'initialize':
            response = {"result": {
                "protocolVersion": "2025-03-26",
                "serverInfo": {"name": "CodeGraphContext", "version": ..., "systemPrompt": LLM_SYSTEM_PROMPT},
                "capabilities": {"tools": {"listTools": True}},
            }}
        elif method == 'tools/list':
            response = {"result": {"tools": list(self.tools.values())}}
        elif method == 'tools/call':
            tool_name = params.get('name')
            args = params.get('arguments', {})
            result = await self.handle_tool_call(tool_name, args)
            response = {"result": {"content": [{"type": "text", "text": json.dumps(result, indent=2)}]}}

        print(json.dumps(response), flush=True)
```

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/server.py:567-653`。注意三点：

- 每行**一个完整 JSON 对象**，没有 Content-Length 头（最简版 MCP，是 stdio variant）。
- `stderr` 用来打 log（Claude Code 抓去显示），**stdout 只走协议**——这就是为什么 003 §B 警告，subprocess reader 线程的 stderr 解码错误**不会污染**协议通道。
- `protocolVersion: "2025-03-26"` 是 hard-coded 的；Claude Code 接受这个版本。

### 3.5 tools/call 的派发

```python
# src/codegraphcontext/server.py:511
async def handle_tool_call(self, tool_name: str, args: Dict[str, Any]) -> Dict[str, Any]:
    tool_map = {
        "add_package_to_graph":     self.add_package_to_graph_tool,
        "find_dead_code":           self.find_dead_code_tool,
        "find_code":                self.find_code_tool,
        "analyze_code_relationships": self.analyze_code_relationships_tool,  # ← 你刚才走的这条
        ...
    }
    handler = tool_map.get(tool_name)
    result = await asyncio.to_thread(handler, **args)
    return result
```

每个 `*_tool` 方法是个超薄包装，只把 `db_manager` / `code_finder` 等共享依赖注进去，转给 handler 模块的纯函数：

```python
# src/codegraphcontext/server.py:292
def analyze_code_relationships_tool(self, **args) -> Dict[str, Any]:

```

## 4. 按工程禁用某些 MCP 工具

如果你不想让 Claude Code 看到 `delete_repository`、`watch_directory` 这种「写操作」，可以在工程根放一个 `mcp.json`（注意名字**没有点**，区别于 `.mcp.json`）：

```json
// F:\codingnet\FSAutoBuildTool\mcp.json
{
  "mcpServers": {
    "CodeGraphContext": {
      "tools": {
        "disabledTools": [
          "delete_repository",
          "watch_directory",
          "unwatch_directory",
          "add_code_to_graph",
          "add_package_to_graph"
        ]
      }
    }
  }
}
```

由 `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/server.py:216 _load_disabled_tools` 读取，在 `_init_tools` 里过滤掉 → Claude Code 的 `tools/list` 拿不到 → LLM 看不见这些工具，自然就调不了。

## 5. 实测追踪：你刚才那次 `who calls DoPerset` 的完整链路

```
1. 你在 Claude Code 输入：「列出谁调用了 DoPerset」
2. Claude 决定调 mcp__CodeGraphContext__analyze_code_relationships
3. Claude Code 把这次调用写到 cgc.exe 的 stdin：
   {"jsonrpc":"2.0","id":42,"method":"tools/call",
    "params":{"name":"analyze_code_relationships",
              "arguments":{"query_type":"find_callers","target":"DoPerset"}}}
4. cgc 主循环 readline() 拿到这行
5. dispatch 到 self.analyze_code_relationships_tool(**args)
6. 转给 analysis_handlers.analyze_code_relationships(code_finder, ...)
7. code_finder 对 KuzuDB 跑：
     MATCH (caller:Function)-[:CALLS]->(callee:Function {name:'DoPerset'})
     RETURN caller, callee
8. KuzuDB 返回 1 行：caller=Main, file=Program.cs, line=153
9. cgc 把结果 json.dumps，包成 JSON-RPC response 写 stdout：
   {"jsonrpc":"2.0","id":42,
    "result":{"content":[{"type":"text","text":"{...}"}]}}
10. Claude Code 读到 stdout 这行，解 JSON，把 content[0].text 喂回给 LLM
11. LLM 拿到结果，组织成自然语言回给你
```

整个过程在「Bug D 修好之后」第 7 步才能返回非空。要不然 KuzuDB 里根本没有 `Function -[:CALLS]-> Function` 边，第 8 步出 0 行，你看到的就是「Found 0 functions that call 'DoPerset'」。这也是为什么 003 §D 是这次链路最关键的一个修复。

## 6. 常见问题

### 6.1 Claude Code 设置面板看 server 状态是 `failed`

读 `stderr`：

```powershell
# Claude Code 设置 → MCP servers → CodeGraphContext → View logs
# 或者手动跑一次试错：
cgc mcp start
# 应该停在 "MCP Server is running. Waiting for requests..."
```

如果 `cgc mcp start` 自己就启动不了，问题在 cgc 一侧，跟 MCP 无关。常见：`.env` 编码错（003 §A）、KuzuDB 路径不可写。

### 6.2 LLM 「找不到工具」

通常是新加的 server 还没 approve。**完全退出** Claude Code（任务栏右键 Quit；只关窗口不算），重新打开，弹窗 Allow。许可记在 `%USERPROFILE%\.claude.json`。

### 6.3 同一工具在 LLM 那里有两份（`mcp__CodeGraphContext__find_code` 和 `mcp__cgc__find_code`）

你在 `~/.claude.json` 和 `<project>\.mcp.json` 里都定义了 server，但 key 不同（`CodeGraphContext` vs `cgc`）。两条都生效，LLM 看到两份。删掉一份即可。

### 6.4 协议版本对不上

`server.py:595` 写死 `"protocolVersion": "2025-03-26"`。Claude Code 新版本可能要求 `2025-06-18` 之类。改这行，重启 cgc，看 server.py 的 commit history 取最新。

## 7. 跟其他 MCP host 的关系

CGC 的 MCP server 不绑定 Claude Code。同样这套协议可以让以下 host 来用：

| Host | 配置文件 | 备注 |
| :--- | :--- | :--- |
| Claude Code | `~/.claude.json` / `<project>\.mcp.json` | 本文重点 |
| Claude Desktop | `~/.config/Claude/claude_desktop_config.json` | mac 上 `~/Library/Application Support/...` |
| Cursor | `<project>\.cursor\mcp.json` | 字段同样是 `mcpServers` |
| VSCode + GitHub Copilot | `.vscode/mcp.json` | 同样 stdio |
| Windsurf | `~/.codeium/windsurf/mcp_config.json` | |
| 任何自写 host | 自己 spawn 子进程做 JSON-RPC | 协议很简单 |

`cgc mcp setup` 向导会针对常见 host 各自写对应的配置文件——但本质上它们消费的都是同一份 `TOOLS` 字典。
