## Bug A：`.env` UTF-8 / GBK 编码不一致

### 现象

```
Warning: Could not load global .env: 'utf-8' codec can't decode byte 0xa1 in position 1828: invalid start byte
No configuration file found. Using defaults.
```

但 `cgc config show` 看着一切正常（误导）。

### 根因

1. `@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/config_manager.py:319` 写 `.env` 不指定 `encoding`，中文 Windows 默认 GBK。
2. `CONFIG_DESCRIPTIONS` 含 em-dash `—`（U+2014），GBK 编为 `\xa1\xaa`。
3. `cli/main.py:349` 用 `python-dotenv.dotenv_values()` 读，dotenv 默认 UTF-8 → 撞 `\xa1` 报错。
4. 被 except 吃掉 → 环境变量**静默丢失**。
5. `config_manager.load_config()` 走另一条 locale 默认路径仍能读 → 双路径行为分裂。

### 修复

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/config_manager.py` 4 处 `open()` 全部加 `encoding="utf-8"`：

| 行号 | 操作 |
| :--- | :--- |
| `:211` | 读全局 `.env` |
| `:224` | 读 local `.env` |
| `:298` | 读现有凭据 |
| `:319` | 写 `.env` |

### 验证

```powershell
Remove-Item "$env:USERPROFILE\.codegraphcontext\.env"
cgc config set SCIP_INDEXER true
$bytes = [IO.File]::ReadAllBytes("$env:USERPROFILE\.codegraphcontext\.env")
($bytes | Where-Object { $_ -eq 0xa1 } | Measure-Object).Count
# 期望：0
```

## Bug B：subprocess 解码崩 reader 线程

### 现象

```
Exception in thread Thread-2 (_readerthread):
...
UnicodeDecodeError: 'gbk' codec can't decode byte 0xae in position 157: illegal multibyte sequence
```

### 根因

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:156-162` 与 `:240-245` 用 `subprocess.run(..., text=True)` 但**没指定 `encoding`**。中文 Windows 默认走 GBK 解码 scip-dotnet 的 stdout，撞到 UTF-8 字节就崩 reader 线程。

### 关键说明

这个错误**不会破坏 SCIP 索引**——`scip-dotnet` 实际跑完、`index.scip` 正常写出。**不要看到这条错误就 Ctrl+C**——一按反而会在 `write_scip_call_edges` 阶段中断事务，留下半成品。

### 修复

两处 `subprocess.run(...)` 都加 `encoding="utf-8", errors="replace"`：

```python
# tools/scip_indexer.py:156-164
result = subprocess.run(
    cmd,
    cwd=str(project_path),
    capture_output=True,
    text=True,
    encoding="utf-8",
    errors="replace",
    timeout=300,
)
```

### 临时解决（PyPI 未修复版）

```powershell
$env:PYTHONIOENCODING = "utf-8"
cgc index F:\codingnet\FSAutoBuildTool
```

## Bug C：SCIP 模式下 `Class -[:CONTAINS]-> Function` 边为空

### 现象

```powershell
cgc query "MATCH (c:Class {name:'PersetConfig'})-[:CONTAINS]->(f:Function) RETURN f.name"
# 返回 []
```

但 `File -[:CONTAINS]-> Function` 边都在。

### 根因

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:619-621` 里 `class_context: None` 被硬编码：

```python
if kind in (26, 17):
    node.update({"cyclomatic_complexity": 1, "decorators": [], "context": None, "class_context": None})
    file_data["functions"].append(node)
```

Tree-sitter 模式各 parser 会真填 `class_context`，writer 据此建 Class→Function CONTAINS。SCIP 模式回归丢了这一步。

### 修复

新增 `_class_context_from_symbol()` 辅助函数（`tools/scip_indexer.py:756-768`），从 SCIP 方法符号 `pkg/Namespace/Class#method().` 里抽出 `#` 前 token 作 class 名。`kind in (26, 17)` 块改为：

```python
if kind in (26, 17):
    cls_ctx = self._class_context_from_symbol(sym) if kind == 26 else None
    node.update({"cyclomatic_complexity": 1, "decorators": [], "context": None, "class_context": cls_ctx})
    file_data["functions"].append(node)
```

仅对 `kind == 26`（method）启用；自由函数（kind 17）保持 None。

### 验证

```powershell
cgc query "MATCH (c:Class)-[:CONTAINS]->(f:Function) WHERE c.path CONTAINS 'FSAutoBuildTool' RETURN c.name AS class_name, count(f) AS methods ORDER BY methods DESC"
```

FSAutoBuildTool 实测：

```
Program: 14, BuildHelper: 10, PersetConfig: 7, PatchHelper: 5, ServerBuilder: 4
14+10+7+5+4 = 40 = Function 节点总数（每方法都正确归属）
```

## Bug D：所有 SCIP CALLS 错归到 File→Function（最影响主线）

### 现象

`cgc find name DoPerset` 能找到 Function 节点，但 `cgc analyze calls / callers DoPerset` 永远返回空。Cypher 查发现：

```powershell
cgc query "MATCH (a:Function)-[r:CALLS]->(b:Function) RETURN count(r) AS func_to_func"
# 0
cgc query "MATCH (a:File)-[r:CALLS]->(b:Function) RETURN count(r) AS file_to_func"
# 136（应该 0 才对）
```

100% 的 CALLS 都被错误写成 `File -[:CALLS]-> Function`。

### 根因链

1. SCIP 协议可选字段 `enclosing_range` 告诉下游「这个定义覆盖哪几行」。
2. CGC 的 `_find_enclosing_definition` 靠它判断「ref 在哪个函数里」，进而建 `Function -[:CALLS]-> Function`。
3. **`scip-dotnet 0.2.x` 不发出 `enclosing_range`**，于是 `_find_enclosing_definition` 永远返回 None。
4. 所有 reference 全部掊进 `module_level_calls_scip` → 写成 `File -[:CALLS]-> Function`。
5. `cgc analyze calls/callers` 查 Function-Function 关系，自然找不到。

### 修复

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:_find_enclosing_definition` 加 fallback 启发式：当**所有**定义都没有 `enclosing_range` 时启动，对一条 ref_line=N 的引用，挑「起始行 ≤ N 且后缀是 `).` 的最大定义」。同时过滤 SCIP 本地变量（`local ` 开头）和类/命名空间（`#` / `/` 后缀）。

```python
if best_enclosing is not None or has_any_enclosing_range:
    return best_enclosing

# fallback for indexers like scip-dotnet that don't emit enclosing_range
fallback_sym: Optional[str] = None
fallback_start = -1
for occ in definition_occurrences:
    sym = occ.symbol
    if sym.startswith("local "):
        continue
    if sym.endswith("/") or sym.endswith("#"):
        continue
    if not sym.rstrip(".").endswith(")"):
        continue
    r = list(occ.range)
    if not r:
        continue
    def_line = r[0] + 1
    if def_line <= ref_line and def_line > fallback_start:
        fallback_sym = sym
        fallback_start = def_line
return fallback_sym
```

仅作备胎；原本发 `enclosing_range` 的 indexer（scip-python / scip-typescript / scip-go…）行为完全不变。

### 验证

```powershell
cgc index F:\codingnet\FSAutoBuildTool --force
cgc query "MATCH (a:Function)-[r:CALLS]->(b:Function) RETURN count(r) AS func_to_func"
# 期望：> 0（实测 136）
cgc query "MATCH (a:File)-[r:CALLS]->(b:Function) RETURN count(r) AS file_to_func"
# 期望：接近 0（实测 0）
cgc analyze calls DoPerset
# 期望：列出 PersetProduction / PersetProfiler / UpdateBuildConfig
```

## Bug E：Windows 上 `cgc delete` / `--force` 看似成功但什么都没删

### 现象

`cgc delete <repo>` 之后查图：

```powershell
cgc query "MATCH (n) WHERE n.path STARTS WITH 'F:\\codingnet\\FSAutoBuildTool' RETURN count(n) AS leftover"
# 大量节点没被删
```

多跑几次 `cgc index --force`，SCIP CALLS 数量**累加**：136 → 156 → 272 → ...

### 根因

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/tools/indexing/persistence/writer.py:1241` 硬编码：

```python
path_prefix = repo_path_str + "/"
```

Windows 上图里存的 path 是 `\\` 分隔。`STARTS WITH "...\FSAutoBuildTool/"` 永远不匹配 `...\FSAutoBuildTool\Program.cs`——节点与边一个都不会被删。

但 Repository 节点本身用 exact match 删（`:1293`），所以「Repository 节点没了 → 后续 `cgc delete` 报 'non-existent repository'」，但其下的 File / Function / Class / CONTAINS / CALLS 等等全部成了孤儿。

### 修复

```python
import os  # 顶部加上

# tools/indexing/persistence/writer.py:1241
path_prefix = repo_path_str + os.sep
```

`os.sep` 在 Windows 上是 `\\`，Linux/macOS 上是 `/`，跨平台正确。

### 验证

```powershell
cgc index F:\codingnet\FSAutoBuildTool
cgc delete F:\codingnet\FSAutoBuildTool
cgc query "MATCH (n) WHERE n.path STARTS WITH 'F:\\codingnet\\FSAutoBuildTool' RETURN count(n) AS leftover"
# 期望：0
cgc query "MATCH ()-[r:CALLS]->() RETURN count(r) AS leftover_calls"
# 期望：0
```

### 临时解决（PyPI 未修复版）

```powershell
Remove-Item -Force "$env:USERPROFILE\.codegraphcontext\global\db\kuzudb"
cgc index F:\codingnet\FSAutoBuildTool
```

直接删整个 KuzuDB 文件重建。会影响 cgc 已索引的其他仓库（如果有）。

## Bug F：所有 `cgc analyze ... --viz` 与 `cgc find ... --viz` 命令静默失效

### 现象

```powershell
cgc analyze callers DoPerset --viz
# 期望：开浏览器渲染调用图
# 实际：直接打印文本表，跟不带 --viz 完全一样
```

`cgc analyze calls/callers/chain/tree/overrides/deps/variable --viz`、`cgc find name/pattern/type --viz` **全部表现一致**——`--viz` 标志被吃掉，没有任何报错。`cgc query "..." --viz` 在第一次调用时会 `ImportError`。

### 根因（4 个连环 bug）

#### F1：`check_visual_flag` 永远返回 False

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/visualizer.py:7-27`：

```python
def check_visual_flag(ctx, visual: bool, cypher_query: str = None):
    if visual and cypher_query:        # ← 必须 visual=True AND cypher_query 非空
        ...
        visualize_helper(repo_path=None, port=port)
        return True
    return False
```

但 `main.py` 的所有 11 个调用点都只传两个参数（`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/main.py:1443/1531/1595/1858/1914/1975/2105/2154/2340/2456`）：

```python
if check_visual_flag(ctx, visual):   # cypher_query 没传 → None → 永远 False
    visualize_call_graph(results, function, direction="incoming")
```

`visual and None` → 永远 False → 永远走文本表分支。

#### F2：所有 `visualize_*` 存根的签名 / 实参不匹配

`visualizer.py:29-51` 全部存根都是 `def visualize_xxx(cypher_query: str)` 一个参数；调用点全是 3 个位置参数：

```python
visualize_call_graph(results, function, direction="incoming")
visualize_inheritance_tree(results, class_name)
visualize_search_results(results, name, search_type="name")
```

如果 F1 修了，立刻 `TypeError: takes 1 positional argument but 3 were given`。

#### F3：存根忽略所有参数

```python
def visualize_call_graph(cypher_query: str):
    visualize_helper(repo_path=None, port=8000)   # ← cypher_query 没用上
```

即便 F1 + F2 修了，存根也只是开**全图视图**，跟具体函数 / 类无关——README 「点击节点看 DoPerset 的 caller」的承诺完全没实现。

#### F4：`cgc query --viz` 路径直接 ImportError

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/cli_helpers.py:411`：

```python
from .visualizer import visualize_cypher_results   # ← 这个名字不存在！
```

`visualizer.py` 里压根没定义 `visualize_cypher_results`。第一次实际触发 `cgc query "..." --viz` 就 `ImportError`。

### 影响范围

| 命令 | 现状 |
| :--- | :--- |
| `cgc visualize --repo <path>` | ✅ **可用**——直接调 `visualize_helper`，不走 `check_visual_flag` |
| `cgc viz --repo <path>` | ✅ 别名，可用 |
| `cgc analyze calls/callers/chain/tree/overrides/deps/variable --viz` | ❌ 静默忽略 |
| `cgc find name/pattern/type --viz` | ❌ 静默忽略 |
| `cgc query "..." --viz` | ❌ ImportError |

### 最小修复（只让 `--viz` 至少打开通用视图）

把 `check_visual_flag` 改成不要求 `cypher_query`，并把每个存根的签名改成 `*args, **kwargs` 吞掉调用点的参数：

```python
# visualizer.py
def check_visual_flag(ctx, visual: bool, cypher_query: str = None):
    if not visual:
        return False
    port = 8000
    if cypher_query:
        encoded = urllib.parse.quote(cypher_query)
        url = f"http://localhost:{port}/explore?cypher_query={encoded}"
        Console(stderr=True).print(f"[cyan]Visualizing:[/cyan] {url}")
    visualize_helper(repo_path=None, port=port)
    return True

def visualize_call_graph(*args, **kwargs):
    visualize_helper(repo_path=None, port=8000)

def visualize_call_chain(*args, **kwargs):
    visualize_helper(repo_path=None, port=8000)

# 同理给其他几个 stub
```

并补一个 `visualize_cypher_results` 定义：

```python
def visualize_cypher_results(records, query: str):
    encoded = urllib.parse.quote(query)
    Console(stderr=True).print(f"[cyan]Visualizing:[/cyan] http://localhost:8000/explore?cypher_query={encoded}")
    visualize_helper(repo_path=None, port=8000)
```

这只是「打开全图」级别的修复，**不实现** README 承诺的「按调用图过滤」「按继承树过滤」。要实现完整功能，每个 `visualize_*` 都得：
1. 把 `results` 转成节点 + 边的 JSON
2. 通过 query string 或 sessionStorage 传给前端
3. 前端读后渲染该子图

是个工程量较大的改动。

### 临时规避（你现在就能用）

只用唯一可用的入口：

# 浏览器自动打开 http://localhost:8000/explore?...&repo_path=...

虽然不是按 `cgc analyze callers DoPerset --viz` 直接定位到 DoPerset 的 caller 子图，但全图加 UI 搜索 + 视觉过滤足够大多数场景。
