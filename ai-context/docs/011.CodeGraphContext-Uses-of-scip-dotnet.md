# 011. CodeGraphContext 对 scip-dotnet 的接口使用清单

> **结论先行**：CGC 把 `scip-dotnet` 完全当作"**黑盒 CLI + SCIP 协议产物**"。整个集成只穿过两道接口：
>
> 1. **进程接口**（CLI）：`scip-dotnet index <sln/csproj> --working-directory <dir> --output <file>` —— 只用 4 个参数。
> 2. **数据接口**（Protobuf）：解析 `index.scip` 里 **`Index` → `Document` → `Occurrence` / `SymbolInformation` → `Relationship`** 的一个小子集字段。
>
> CGC **不引用** `scip-dotnet` 的任何 .NET 程序集，**不调用**其 Roslyn 内部 API，**不依赖**其 `ScipDocumentIndexer`/`ScipProjectIndexer`/`ScipSymbol` 这些 C# 类型；它们只通过 `.scip` 文件间接体现。
>
> 相关文档：
> - C# 工程实操：`@d:/ai-lab/CodeGraphContext/ai-context/docs/001.SCIP-CSharp-FSAutoBuildTool-Guide.md`
> - SCIP vs Roslyn 备选方案：`@d:/ai-lab/CodeGraphContext/ai-context/docs/008.CGC-vs-MCP-Roslyn-for-Large-CSharp-Game.md`

## 2. 数据接口：CGC 解析 `index.scip` 的字段清单

入口在 `@d:/ai-lab/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:452-465`：


> **注意**：CGC 自带的 `scip_pb2.py` 是 **新版** SCIP schema（带 `kind` / `display_name` / `enclosing_range` / `signature_documentation`）；而 `scip-dotnet` 仍在用 **旧版** `scip.proto`（见 `@d:/ai-lab/scip-dotnet/scip.proto:175-186`），**不写**这些新字段。CGC 用 `getattr(occ, "symbol_roles", getattr(occ, "role", 0))` 这样的兼容写法读，C# 输出里读出来全是默认值，CGC 用启发式补齐（§4）。

## 3. 符号串协议：CGC 怎么"解码"scip-dotnet 的 `symbol` 字符串

scip-dotnet 的符号串遵循 SCIP grammar，由 `ScipSymbol.cs` 拼接（见 `@d:/ai-lab/scip-dotnet/ScipDotnet/ScipSymbol.cs:36-48`）：

```
<symbol> ::= 'local ' <id>
           | <scheme> ' ' <package> ' ' (<descriptor>)+

<descriptor> 后缀：
  '/' = Namespace
  '#' = Type
  '.' = Term (field/property/event/...)
  '(<disambig>).' = Method
  '(<name>)'      = Parameter
  '[<name>]'      = TypeParameter
  ':<name>'       = Meta
```

### 3.1 scip-dotnet 的固定头部

来自 `@d:/ai-lab/scip-dotnet/ScipDotnet/ScipSymbol.cs:26-34`：

- **scheme** 恒为 `scip-dotnet`
- **manager** 恒为 `nuget`
- 当 `--allow-global-symbol-definitions=false`（CGC 默认）且符号在源码中有定义：`package` 退化为占位包 `IndexLocalPackage = "scip-dotnet nuget . . "`
- 否则用真实 `ContainingAssembly.Identity.Name` + `Version`

所以 CGC 看到的典型 C# 符号长这样：

```
scip-dotnet nuget . . FSAutoBuildTool/PersetConfig#DoPerset().
└── scheme ─┘└─ pkg ─┘└────── namespace/type/method ──────┘
```

### 3.2 CGC 的解析器函数

代码位置：`@d:/ai-lab/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:685-700`

```@d:/ai-lab/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:685-700
    def _name_from_symbol(self, symbol: str) -> str:
        import re
        # scip-clang appends a hash in parentheses to disambiguate overloads / template args
        s = re.sub(r"\([0-9a-fA-F]{4,}\)\.?$", "", symbol)
        # Strip parameter descriptors: .($param), .($p1).($p2), etc.
        s = re.sub(r"\.\(\$?[^)]*\)", "", s)
        s = s.rstrip(".#")
        # Remove function/method call markers: ()
        s = re.sub(r"\(\)\.?$", "", s)
        parts = re.split(r"[/#]", s)
        name = parts[-1] if parts else symbol
        name = re.sub(r"^`([^`]+)`$", r"\1", name)
        # Handle space-separated package descriptors (PHP: "project 1.0.0 Animal")
        if " " in name:
            name = name.rsplit(" ", 1)[-1]
        return name
```

辅助：`_class_context_from_symbol`（`scip_indexer.py:756-768`）—— 从 `Type#method().` 切出 `Type` 名，写入函数节点的 `class_context` 属性，CGC 据此连 `Class -[:CONTAINS]-> Function`。

## 4. 启发式补齐：scip-dotnet 不写的字段怎么办

因为 `scip-dotnet` 的 `scip.proto` 落后于 CGC 自带的 `scip_pb2.py`，三个新字段 (`SymbolInformation.kind`、`SymbolInformation.display_name`、`Occurrence.enclosing_range`) 在 C# 索引里恒为空/0。CGC 用源码启发式补：

### 4.1 推 `kind`

代码位置：`@d:/ai-lab/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:583-607`


对 C# 的 net effect：

| scip-dotnet 写的后缀 | scip-dotnet 内部 Roslyn 类型 | CGC 推出的 SCIP `kind` | CGC 入图节点 |
| :--- | :--- | :--- | :--- |
| `().` 且含 `#` | `IMethodSymbol`（非 LocalFunction） | 26 (Method) | `Function`（带 `class_context`） |
| `().` 不含 `#` | — (C# 不出现) | 17 (Function) | `Function` |
| `#` + 源码 `interface` | `INamedTypeSymbol` (interface) | 20 (Interface) | `Interface` |
| `#` + 源码非 interface | `INamedTypeSymbol` (class/struct/enum/delegate) | 7 (Class) | `Class` |
| `.` 结尾 | property/field/event | 0 → 不入图 | （丢弃）|

> **已知简化**：C# 的 `struct`/`enum`/`delegate` 都被 CGC 当作 `Class` 入图，因为启发式只查 `interface`/`trait` 前缀（`scip_indexer.py:600-607`）。

### 4.2 推 `enclosing range`（caller 归属）

代码位置：`@d:/ai-lab/CodeGraphContext/src/codegraphcontext/tools/scip_indexer.py:770-803`

scip-dotnet 不写 `enclosing_range` → 没有任何 `occ.enclosing_range`，触发 fallback 分支：按定义行号往前最近的、以 `)` 结尾的方法定义当作 caller。这是 CGC 对 C# 调用边 (`CALLS`) 的核心猜测逻辑——也是 003 文档里"`Function-Function` 主导，`file_to_func ≈ 0`"那条质量指标的来源。

## 7. 没有用到的能力

便于以后扩展时知道哪些是"已有原料没吃"：

- **scip-dotnet CLI**：`--include`、`--exclude`、`--allow-global-symbol-definitions`、`--dotnet-restore-timeout`、`--skip-dotnet-restore`、`--nuget-config-path` —— 全部走默认。
- **SCIP 协议**：`Metadata.project_root` / `tool_info`、`Document.language`、`Occurrence.syntax_kind`、`Occurrence.override_documentation`、`Occurrence.diagnostics`、`Relationship.is_reference` / `is_type_definition` / `is_definition`、`SymbolInformation` 的新 `signature_documentation`。
- **隐含语义**：scip-dotnet 写的 `Relationship.is_reference=true`（标记 override 方法的 inverse 关系，见 `ScipDocumentIndexer.cs:302-318`）CGC 完全忽略，只取 `is_implementation`。

任何想从图谱里挖出"override 链路"、"interface 反向实现链"、"诊断信息"或者"NuGet 包符号准确定位"，都需要先把这些字段接上来。

## 8. 一句话总结

CGC 把 `scip-dotnet` 当作 **"输入 4 个 CLI 参数 → 输出一个 `.scip` protobuf 文件"** 的纯文件级合约。读取面非常窄：`Document.{relative_path, occurrences, symbols}` + `Occurrence.{range, symbol, symbol_roles}` + `SymbolInformation.{documentation, relationships}` + `Relationship.{symbol, is_implementation}`，共 **9 个**字段。其余所有语义（节点类型、调用归属、继承链）都是 CGC 自己在 Python 里用符号字符串后缀 + 源码行启发式重建出来的。
