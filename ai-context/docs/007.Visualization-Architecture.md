# 007. CGC 可视化系统 (`--viz`) 架构

> 题图：你看到的「精美交互式知识图谱」实际上是 **Vite + React + Sigma.js / react-force-graph 的 SPA**，由本地 **uvicorn + FastAPI** 临时起一个 `127.0.0.1:8000` 后端供数据，**不是真正的独立 HTML**。本文按真实代码讲清楚。
>
> 相关文档：CLI 命令清单见 `@e:/claude-hub/CodeGraphContext/ai-context/docs/001.SCIP-CSharp-FSAutoBuildTool-Guide.md` §7。

---

## 0. TL;DR

| 维度 | 实际情况 |
| :--- | :--- |
| 触发命令 | `cgc analyze ... --viz` / `cgc find ... --viz`，等价别名 `--visual` / `-V` |
| 后端 | FastAPI + uvicorn，端口默认 8000，**只绑定 127.0.0.1** |
| 前端 | Vite 打包的 React SPA（在 `src/codegraphcontext/viz/dist/`） |
| 图渲染 | **Sigma.js + graphology**（节点多时） + **react-force-graph-2d/3d**（力导向） + **three.js**（3D） |
| UI 库 | shadcn/ui（Radix UI primitives） + Tailwind CSS + framer-motion + lucide-react |
| 字体 | Outfit（UI）+ JetBrains Mono（代码）——通过 Tailwind 配置 |
| 是否「独立 HTML」 | **不是**。前端是 SPA，调用本地 uvicorn 的 `/api/graph` 拿数据。关闭 cgc 后页面失效 |
| 安全 | CORS regex 限 localhost；Cypher 写关键字（`CREATE`/`MERGE`/`DELETE`/...）服务端拒绝 |

### 1.2 实测**不工作** ❌

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/main.py` 里所有标了 `--visual / --viz / -V` 的命令：

| 命令 | 现状 | 说明 |
| :--- | :--- | :--- |
| `cgc analyze calls <fn> --viz` | ❌ 静默忽略 | 文本表照常打印，没起 server |
| `cgc analyze callers <fn> --viz` | ❌ 静默忽略 | 同上（实测就这条踩坑） |
| `cgc analyze chain <a> <b> --viz` | ❌ 静默忽略 | |
| `cgc analyze tree <Class> --viz` | ❌ 静默忽略 | |
| `cgc analyze overrides <fn> --viz` | ❌ 静默忽略 | |
| `cgc analyze deps <module> --viz` | ❌ 静默忽略 | |
| `cgc analyze variable <var> --viz` | ❌ 静默忽略 | |
| `cgc find name <name> --viz` | ❌ 静默忽略 | |
| `cgc find pattern <regex> --viz` | ❌ 静默忽略 | |
| `cgc find type <type> --viz` | ❌ 静默忽略 | |
| `cgc query "<cypher>" --viz` | ❌ ImportError | 第一次用就崩 |

根因（4 个连环 bug）：

1. `check_visual_flag(ctx, visual)` 内部判断 `if visual and cypher_query`——**所有调用点都没传 cypher_query**，永远 False
2. 即便修了 1，`visualize_call_graph(results, function, direction=...)` 这种 3 参调用对应 stub 是 1 参——TypeError
3. 即便修了 1+2，stub 内部忽略所有参数，只开**全图**，跟具体函数无关——README 承诺的「DoPerset 的 caller 子图」实现为 0
4. `cgc query --viz` 路径 `from .visualizer import visualize_cypher_results`，但 `visualizer.py` 里**根本没定义**这个名字

完整源码定位与最小修复方案见 `@e:/claude-hub/CodeGraphContext/ai-context/docs/003.SCIP-CGC-Windows-Bugs-And-Fixes.md` §Bug F。

## 2. 触发后的完整流程

```
┌─ 1. cgc analyze calls DoPerset --viz ────────────────────────────────┐
│   typer 命令解析，visual=True                                         │
└──────────────────────────┬───────────────────────────────────────────┘
                           ▼
┌─ 2. check_visual_flag(ctx, visual=True) ─────────────────────────────┐
│   返回 True → 走可视化分支                                            │
└──────────────────────────┬───────────────────────────────────────────┘
                           ▼
┌─ 3. visualize_helper(repo_path=None, port=8000) ─────────────────────┐
│   ① 找静态目录：先 src/codegraphcontext/viz/dist                     │
│      回退顺序：website/dist → cwd/website/dist                        │
│   ② set_db_manager(db_manager) — 把 KuzuDB 连接交给 FastAPI 全局     │
│   ③ 在 daemon 线程里 1.5s 后用 webbrowser.open() 打开 URL            │
│   ④ uvicorn.run(host=127.0.0.1, port=8000) — 阻塞主线程              │
└──────────────────────────┬───────────────────────────────────────────┘
                           ▼
┌─ 4. 浏览器打开 http://localhost:8000/explore?backend=http://...&... ─┐
│   FastAPI 的 SPA fallback 返回 viz/dist/index.html                   │
│   React 应用挂载，从 query string 读 backend URL                      │
└──────────────────────────┬───────────────────────────────────────────┘
                           ▼
┌─ 5. 前端 fetch('http://localhost:8000/api/graph?repo_path=...') ─────┐
│   后端跑 Cypher → 解析 KuzuDB / Neo4j / FalkorDB 节点+边             │
│   返回 {nodes, links, files, fileContents}                            │
└──────────────────────────┬───────────────────────────────────────────┘
                           ▼
┌─ 6. 前端用 Sigma 或 react-force-graph 把数据渲染成图 ────────────────┐
│   交互：点节点 → 侧边栏；搜索框过滤；力导向/分层布局切换              │
└──────────────────────────────────────────────────────────────────────┘
```

**进程在 4 之后阻塞**——你 Ctrl+C 才会退 uvicorn 和 cgc。**关掉浏览器不会停服务**。

## 3. 后端实际只有 3 个 endpoint

`@e:/claude-hub/CodeGraphContext/src/codegraphcontext/viz/server.py`：

| Endpoint | 作用 |
| :--- | :--- |
| `GET /api/graph?repo_path=...&cypher_query=...` | 返回 `{nodes, links, files, fileContents}`。`cypher_query` 走 read-only 校验（`_is_read_only_cypher`），写关键字直接 400 |
| `GET /api/file?path=<abs path>` | 返回单文件内容 |
| `GET /{full_path:path}` | SPA fallback——存在的静态文件直接返回，否则一律返回 `index.html`（让 React Router 接管） |

CORS 限制：

```python
_ALLOWED_ORIGIN_REGEX = r"^https?://(localhost|127\.0\.0\.1)(:\d+)?$"
app.add_middleware(CORSMiddleware, allow_origin_regex=_ALLOWED_ORIGIN_REGEX, allow_methods=["GET"])
```

只接 `localhost` / `127.0.0.1`，方法只允许 `GET`。这意味着远程 / 其他设备拿不到数据。

## 5. 「独立 HTML 文件」的真相

README 写的：

> 零依赖查看：独立的 HTML 文件，可在任何现代浏览器中运行。

实际：

| 维度 | 真相 |
| :--- | :--- |
| 需要 Python 进程吗？ | **需要**。你用 `cgc analyze ... --viz` 启动的 uvicorn 必须保持运行，否则前端 fetch `/api/graph` 失败白屏 |
| 关 cgc 进程后页面还能用吗？ | **不能**。前端无法从内存重建图（节点详情等需要 `/api/file` 拉源码） |
| 「独立」指的是什么？ | 大概是「**不依赖外部服务**」——KuzuDB 是嵌入式的、没有 Neo4j Server 也行、前端是预编译 SPA 不用 npm。但**仍然需要本机 Python 跑后端** |
| 想真正离线分享一张静态图怎么办？ | 当前**做不到**直接产生 self-contained HTML。需要自己截图，或写脚本把 `/api/graph` 的 JSON 嵌入到一份魔改 SPA 里 |

如果你想要真正一键分享的离线图，目前只有「截屏」或「`cgc visualize` 配合 Neo4j Browser 那类外部工具」。`--viz` 是**本地交互式探索**，不是**离线分发**。

## 6. wheel 里要包含的静态资产

`viz/dist` 必须随 wheel 一起发布，否则用户装好 cgc 跑 `--viz` 直接报错：

```python
# @e:/claude-hub/CodeGraphContext/src/codegraphcontext/cli/cli_helpers.py:486-504
console.print("[bold red]Visualization assets not found.[/bold red]")
console.print(
    "[dim]If you installed from PyPI, upgrade after the next release "
    "(wheels must bundle viz/dist). If you are developing from source, run:[/dim]"
)
console.print("  [cyan]./scripts/sync_viz_dist.sh[/cyan]")
```

build 流程：

```bash
cd website && npm ci && npm run build         # 产生 website/dist
./scripts/sync_viz_dist.sh                    # 把 website/dist → src/codegraphcontext/viz/dist
python -m build                               # 打 wheel，viz/dist 进 sdist + wheel
```

你这台 editable 装的环境**不一定有** `viz/dist`。验证：

```powershell
Get-ChildItem "e:\claude-hub\CodeGraphContext\src\codegraphcontext\viz" -ErrorAction SilentlyContinue
```

如果没有 `dist` 子目录，`cgc ... --viz` 会按 `@cli_helpers.py:468-504` 的回退顺序找：

1. `src/codegraphcontext/viz/dist/`（首选）
2. `<project_root>/website/dist/`（开发时回退）
3. `<package_root>.parent.parent/website/dist/`（不同 layout 的回退）
4. `<cwd>/website/dist/`（最后兜底）

都找不到就报错退出。

## 8. 故障排查

| 现象 | 原因 | 修 |
| :--- | :--- | :--- |
| `Visualization assets not found` | `viz/dist` 没生成 | 跑 §7.1 build + copy |
| 浏览器白屏，devtools 报 CORS | host 不在 `localhost`/`127.0.0.1` 正则里（如 `0.0.0.0` 或外网） | uvicorn 严格绑 127.0.0.1，不要改 `host=` |
| `400 Bad Request — only supports read-only Cypher` | Cypher 里有 `CREATE`/`MERGE`/`DELETE`/`SET`/`REMOVE`/`DROP`/`CALL apoc` | 改成 read-only，或用 `cgc query`（无 viz）走 MCP 路径 |
| 节点 0 边 0 | 数据库里相应关系不存在（如 `CALLS` 边没建立——见 003 §D Bug D） | 先 `cgc query "MATCH (a)-[:CALLS]->(b) RETURN count(*)"` 验证 |
| 浏览器没自动开 | Windows 上 `webbrowser.open()` 偶发失败 | 手动复制日志里的 `http://localhost:8000/explore?...` 粘到浏览器 |
| 想给团队展示 | 把 `localhost:8000` 用 ngrok / Cloudflare Tunnel 暴露 | **不推荐**——CORS regex 会拒绝外部域名；改完 regex 还要小心 read-only 校验是否够 |

## 9. 进程模型小结

`cgc analyze ... --viz` 期间：

```
你的 PowerShell                            子进程关系
──────────────────                       ──────────────────────────────
cgc.exe (主进程)
├─ uvicorn 主线程 (阻塞 main 直到 Ctrl+C)
├─ KuzuDB driver session（共享 DB 连接给 FastAPI）
└─ daemon 线程（1.5s 后调 webbrowser.open）

浏览器（独立进程）
└─ React SPA → fetch('http://127.0.0.1:8000/api/graph?...')
```

**不是 MCP 服务器**——这跟 `cgc mcp start` 是完全不同的进程，端口、协议、目的都不一样：

| 维度 | `cgc mcp start` | `cgc analyze ... --viz` |
| :--- | :--- | :--- |
| 协议 | stdio JSON-RPC | HTTP (FastAPI) |
| 端口 | 无 | 8000 |
| 谁连 | LLM host (Claude Code) | 浏览器 |
| 进程多久 | host 关之前一直在 | 你 Ctrl+C 之前一直在 |
| 共用 KuzuDB？ | 是 | 是 |
