# 010. gdep 的 Roslyn 代码图 vs `009.RoslynGraphContext` 设计 — 对比留档

> **触发问题**：`@d:\ai-lab\graphify\ai-context\docs\009.gdep-深度拆解-Graphify可借鉴点.md:153-161` 的"启发式补偿表"是否说明 gdep 的 C# 代码图比 `@d:\ai-lab\CodeGraphContext\ai-context\docs\009.RoslynGraphContext-Architecture-for-CSharp-Game.md` 还要好？
>
> **简答**：**不是**。在纯 C# 代码图谱的语义精度维度上，`009.RoslynGraphContext` 的设计远优于 gdep。但这是**"已上线实物" vs "10–14 周路线图"**的不对等比较——gdep 在 C# 代码图之外还覆盖了 RoslynGraphContext 完全没有规划的资产层、confidence 透明化、wiki 缓存等能力。两者是**互补关系**，不是替代关系。
>
> **本文目的**：把这次对比留档，作为后续"是否在 RoslynGraphContext 中借鉴 gdep 思路"决策的参考。

## 1. 关键事实校准

引用源文档对 gdep 的描述（`@d:\ai-lab\graphify\ai-context\docs\009.gdep-深度拆解-Graphify可借鉴点.md:108-112`）：

> **特征**：
> - 用 `CSharpSyntaxTree.ParseText(code)` + `GetCompilationUnitRoot()`——**仅语法树，无 SemanticModel**
> - Unity / UniTask 常用类型写死在 `Primitives` 白名单……
> - 支持 `partial class` 跨文件合并
> - 提取 `MethodInfo` / `FieldInfo` / `ParsedEdge` 三层结构

`L153-L161` 的"启发式补偿表"是 gdep **自己承认的短板自白**：

| 真实 Roslyn SemanticModel 提供 | gdep 用什么模拟 |
|--------------------------------|-----------------|
| 字段类型解析 | `MemberTypes` 字典（首次扫描时收集声明） |
| 方法返回类型 | `ReturnTypes` 字典 |
| 静态访问 / 单例 | `StaticAccessors` + `hints.json` 手动声明 |
| 重载分发 | 同名方法合并、按调用上下文模糊匹配 |
| 跨程序集 | 不支持（只在当前项目内启发式） |

而 `009.RoslynGraphContext` 的设计起点（`@d:\ai-lab\CodeGraphContext\ai-context\docs\009.RoslynGraphContext-Architecture-for-CSharp-Game.md:81-89`）：

```csharp

foreach (var project in _solution.Projects)
{
    var compilation = await project.GetCompilationAsync();
    foreach (var syntaxTree in compilation.SyntaxTrees)
    {
        var semanticModel = compilation.GetSemanticModel(syntaxTree);
        ...
```

——直接拿到完整 `SemanticModel`，**根本不需要启发式补偿**。

## 2. 维度逐项对比

### 2.1 编译入口（决定一切的起点）

| 维度 | gdep 实际做法 | RoslynGraphContext 设计 |
|------|--------------|------------------------|
| API | `CSharpSyntaxTree.ParseText(code)` | `MSBuildWorkspace.OpenSolutionAsync(sln)` |
| 编译产物 | **只有语法树** | 完整 `Compilation` + 所有 `SemanticModel` |
| 跨文件/跨项目解析 | ❌ 仅当前项目启发式 | ✅ Solution 内全量 |
| 跨程序集（NuGet/SDK） | ❌ | ✅ |
| Source Generator 产物 | ❌ | ✅ |
| 编译失败时 | ✅ 仍可工作（容错强） | ⚠️ MSBuild 失败 → 整体退化 |

### 2.2 调用边的精度（图谱质量的命门）

**gdep**（`@d:\ai-lab\graphify\ai-context\docs\009.gdep-深度拆解-Graphify可借鉴点.md:122-150`）：
- 用 `MemberTypes` / `ReturnTypes` / `StaticAccessors` 三个字典做"伪类型推断"
- 重载靠**同名方法合并 + 调用上下文模糊匹配**
- 单例靠 `hints.json` **手工声明**

**RoslynGraphContext**（`@d:\ai-lab\CodeGraphContext\ai-context\docs\009.RoslynGraphContext-Architecture-for-CSharp-Game.md:642-660`）：

```csharp
var symbolInfo = _model.GetSymbolInfo(node);
if (symbolInfo.Symbol is IMethodSymbol callee)
{
    _graph.AddEdge(new CallsEdge(
        callerMethod: _currentMethod,
        calleeFullName: callee.OriginalDefinition.ToDisplayString(),
        ...
        isExtensionMethod: callee.IsExtensionMethod,
        reducedFrom: callee.ReducedFrom?.ToDisplayString(),
    ));
}
```

**差距**：gdep 的 INFERRED 边假阳性率不可控；RoslynGraphContext 的边是编译器级别的真理。

## 3. gdep 的真实优势（不在"代码图"维度）

| 优势 | gdep | RoslynGraphContext |
|------|:---:|:---:|
| **Unity 资产图**（Prefab / Scene GUID 反向） | ✅ 生产级（`unity_refs.py`） | ❌ 设计里完全没规划资产层 |
| **UnityEvent persistent calls 反向** | ✅ | ❌ |
| **Animator 状态机解析** | ✅ | ❌ |
| **未使用资产检测** | ✅ | ❌ |
| **不依赖编译成功** | ✅ 语法树容错 | ❌ MSBuild 必须通过 |
| **confidence 透明化**（HIGH/MEDIUM/LOW + coverage） | ✅ `confidence.py` | ❌ 设计未提 |
| **Wiki 缓存**（FTS5 BM25 跨会话） | ✅ | ❌ |
| **多引擎支持** | ✅ Unity + UE5 + Axmol + .NET + C++ | ❌ 仅 C# |
| **MCP 工具丰富度** | 30 个（含资产/lint/diff） | 38 个（全部代码维度） |
| **lint 反模式规则** | ✅ 19 条 Unity 规则 | ❌ |

> 关键观察：**gdep 的差异化优势全部在"非代码图"维度**——资产、缓存、透明化、多引擎。RoslynGraphContext 的差异化优势全部在"代码图深度"维度——真语义、重构、诊断。

## 4. 一句话总结

| 比较维度 | 胜者 | 差距程度 |
|---------|:---:|:--------:|
| **C# 代码语义精度** | RoslynGraphContext | 数量级（真编译器 vs 启发式字典） |
| **C# Schema 丰富度** | RoslynGraphContext | 显著（多 4 种关系、4 种节点） |
| **C# 重构 / 诊断能力** | RoslynGraphContext | 唯一（gdep 完全没有） |
| **整体游戏项目可用性** | gdep | 显著（覆盖资产层 + 已上线） |
| **冷启动速度** | gdep | 数量级（秒级 vs 分钟级） |
| **不依赖编译成功** | gdep | 唯一（gdep 容错，RGC 必须 MSBuild 过） |
| **confidence 透明化 / 缓存** | gdep | 唯一（RGC 设计未规划） |
| **当前可用性** | gdep | 唯一（一个已发版，一个还是 PPT） |

**结论**：

- 单看你引用的 `L153-L161` 那张表 → 那是 gdep 的**短板**，不是优点。
- `009.RoslynGraphContext` 的设计**就是为了消除那张表里的所有"模拟"项**——一旦落地，C# 代码图会全面碾压 gdep。
- 但若目标是百万行 **Unity 游戏项目** 的端到端分析，**只有 RoslynGraphContext 不够**——必须把 gdep 的资产层、confidence、wiki 思路融合进来。
