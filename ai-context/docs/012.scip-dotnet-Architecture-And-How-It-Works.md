# 012. scip-dotnet 工作原理深度解析

> **一句话定性**：`scip-dotnet` 是一座 **"Roslyn ISymbol → SCIP Protobuf"** 的桥。它本身不做编译、不做类型推断，全靠 Roslyn 把 C#/VB 源码搞成 `ISymbol` + `SemanticModel`，自己只负责把每个 `ISymbol` 翻译成一个**稳定的 SCIP 符号字符串**，再加上少量结构化元数据，序列化成 `index.scip` 文件。
>
> 仓库版本特征（关键依赖）：
> - **Microsoft.CodeAnalysis 4.4.0**（Roslyn 主体）
> - **Microsoft.CodeAnalysis.Workspaces.MSBuild 4.4.0**（加载 `.sln` / `.csproj`）
> - **Microsoft.Build.Locator 1.7.8**（找系统里的 MSBuild）
> - **Google.Protobuf 3.30.0**（SCIP 序列化）
> - **System.CommandLine** + **System.CommandLine.Hosting**（CLI + DI 主机）
> - 目标框架：`net6/7/8/9/10` 多目标
>
> 相关：`@d:/ai-lab/CodeGraphContext/ai-context/docs/011.CodeGraphContext-Uses-of-scip-dotnet.md`（CGC 怎么消费这个工具的输出）。

### 2.2 顶层 Index 装配

```@d:/ai-lab/scip-dotnet/ScipDotnet/IndexCommandHandler.cs:86-115
    private static async Task ScipIndex(IHost host, IndexCommandOptions options)
    {
        var stopwatch = Stopwatch.StartNew();
        var indexer = host.Services.GetRequiredService<ScipProjectIndexer>();
        var index = new Scip.Index
        {
            Metadata = new Metadata
            {
                ProjectRoot = new Uri(new Uri("file://"), options.WorkingDirectory.FullName).ToString(),
                ToolInfo = new ToolInfo
                {
                    Name = "scip-dotnet",
                    Version = "0.1.0-SNAPSHOT"
                },
                TextDocumentEncoding = TextEncoding.Utf8,
            }
        };
        await foreach (var document in indexer.IndexDocuments(host, options))
        {
            index.Documents.Add(document);
        }

        if (index.Documents.Count <= 0)
        {
            options.Logger.LogWarning("Indexing finished without error but no documents were indexed.");
        }

        await File.WriteAllBytesAsync(options.Output.FullName, index.ToByteArray());
```

要点：

- **`Index` 是构建期累加的**：`ScipProjectIndexer.IndexDocuments` 返回 `IAsyncEnumerable<Document>`，每个文档处理完即吐，主循环 `index.Documents.Add(document)` 累积。这是流式编排，但**最终序列化是一次性 `ToByteArray()` 整体写盘**——所以大仓库内存峰值仍然是 O(整个索引)。
- **Tool 版本号写死成 `0.1.0-SNAPSHOT`**：与 `ScipDotnet.csproj` 里的真实 `<Version>0.2.14</Version>`（`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDotnet.csproj:7`）**不同步**。这是源码层面的 bug／历史包袱，不影响功能但影响 `Metadata.tool_info.version`。
- **`ProjectRoot` 是 `file://` URI**：MSBuild 工作目录的绝对路径。所有 `Document.relative_path` 都以这个为基准。

## 3. 工程编排 —— `ScipProjectIndexer.cs`

代码：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipProjectIndexer.cs:1-159`

这一层负责 **"从一堆 .sln/.csproj 拿到能 walk 的 Roslyn `Document`"**，处理三件难事：NuGet restore、多目标框架去重、include/exclude 过滤。

### 3.1 NuGet restore 前置

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipProjectIndexer.cs:21-43
    private void Restore(IndexCommandOptions options, FileInfo project)
    {
        var arguments = project.Extension.Equals(".sln") ? $"restore {project.FullName} /p:EnableWindowsTargeting=true" : "restore /p:EnableWindowsTargeting=true";
        if (options.NugetConfigPath != null)
        {
            arguments += $" --configfile \"{options.NugetConfigPath.FullName}\"";
        }
        var process = new Process()
        {
            StartInfo = new ProcessStartInfo()
            {
                WorkingDirectory = options.WorkingDirectory.FullName,
                FileName = "dotnet",
                Arguments = arguments
            }
        };
        options.Logger.LogInformation("$ dotnet {Arguments}", arguments);
        process.Start();
        if (!process.WaitForExit(options.DotnetRestoreTimeout))
        {
            Logger.LogWarning("Dotnet restore did not finish in {Time} milliseconds, the results of the indexing might be incorrect.", options.DotnetRestoreTimeout);
        }
    }
```

要点：

- **走 `dotnet restore` 命令行**，不调用 MSBuild API。原因是 NuGet restore 本身需要联网+重写 `obj/`，独立子进程更稳。
- **`/p:EnableWindowsTargeting=true`**：允许 Linux/macOS 上索引 Windows-only 工程（如 WPF）。这是一个为了跨平台索引特意打开的开关。
- **超时不阻断**：超时只打 `LogWarning`，索引继续——后果是 `MSBuildWorkspace.OpenProjectAsync` 可能因为缺包失败，最终生成的 `Index.documents` 里少符号或是空。
- **可被 `--skip-dotnet-restore` 跳过**：CI 里通常上一步已经 restore 完毕，跳过省时间。

### 3.3 多目标框架的去重

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipProjectIndexer.cs:78-94
        var projectsPerProjFile = projects.GroupBy(x => x.FilePath);
        var framework = $"net{Environment.Version.Major}.0";
        foreach (var projectGroup in projectsPerProjFile)
        {

            // If the project was found by opening the solution, we need to find the project that matches the framework.
            // if we can' fall back to the first one. Without this, we will process the same document multiple times
            // once for each framework version being targeting and it leads to unpredictable results since the scip file
            // will contain the same document multiple times iwth different symbols.
            var project = projectGroup.FirstOrDefault(x => x.Name.Contains($"({framework})", StringComparison.OrdinalIgnoreCase)) ?? projectGroup.First();
            if (project.Language != "C#" && project.Language != "Visual Basic")
            {
                Logger.LogWarning(
                    "Skipping project {ProjectFilePath} because it has language {ProjectLanguage} and scip-dotnet currently only supports C# and Visual Basic.",
                    project.FilePath, project.Language);
                continue;
            }
```

**关键设计**：一个 `<TargetFrameworks>net6.0;net8.0</TargetFrameworks>` 的 csproj 在 `MSBuildWorkspace.OpenSolutionAsync` 里会展开成 **N 个 `Project` 实例**——每个目标框架一个。如果不去重，同一个 `Document` 会被索引 N 次，最终 `Index.documents` 里出现重复 path、不同符号——这是真坑。

去重策略：用**当前进程运行的 .NET 版本**（`Environment.Version.Major`）匹配 project 名里的 `(netX.0)` 后缀，匹配不到就退化为第一个。这意味着：

- 进程跑在 .NET 8 → 偏向选 `(net8.0)` 那份 project
- 用户的 csproj 不一定 target net8 → 退化用第一个 → 可能丢方法/类型符号（如果第一个目标框架不支持某些 API）

> 如果在 net6 进程里索引 net10 工程，会发生什么？退化到第一个，**可能**索引正确，**可能**因为 net10 引用了 net6 没有的 API 而导致 `SemanticModel` 报错——但因为 scip-dotnet 不区分 binding 错误和正常符号缺失，最终就是符号丢失。CGC 在 Windows 上指定用 .NET 8 runtime（001 文档）就是这个原因。

### 3.5 单文档索引

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipProjectIndexer.cs:122-158
    private async Task<Scip.Document> IndexDocument(Document document,
                                                    IndexCommandOptions options,
                                                    Dictionary<ISymbol, ScipSymbol> globals,
                                                    string language)
    {
        Scip.Document doc = new()
        {
            Language = language,
            RelativePath = document.FilePath == null
                ? null
                : Path.GetRelativePath(options.WorkingDirectory.FullName, document.FilePath)
        };
        var semanticModel = await document.GetSemanticModelAsync();
        if (semanticModel == null)
        {
            Logger.LogWarning(
                "Skipping document {DocumentFilePath} because document.GetSemanticModelAsync() returned null",
                document.FilePath);
        }
        else
        {
            var symbolFormatter = new ScipDocumentIndexer(doc, options, globals);
            var root = await document.GetSyntaxRootAsync();
            if (language == "C#")
            {
                var walker = new ScipCSharpSyntaxWalker(symbolFormatter, semanticModel);
                walker.Visit(root);
            }
            else if (language == "Visual Basic")
            {
                var walker = new ScipVisualBasicSyntaxWalker(symbolFormatter, semanticModel);
                walker.Visit(root);
            }
        }

        return doc;
    }
```

四个动作，照顺序：

1. 创建空的 `Scip.Document`，设 `Language` + `RelativePath`（用 `Path.GetRelativePath(workingDirectory, ...)`，决定 011 文档里 CGC 看到的相对路径）。
2. **`GetSemanticModelAsync()`** —— Roslyn 现做现绑定，返回 null 表示 binding 失败（最常见原因：缺 NuGet 引用）。
3. **`GetSyntaxRootAsync()`** —— 拿 AST 根。
4. 按语言分发到 `ScipCSharpSyntaxWalker` 或 `ScipVisualBasicSyntaxWalker`，两者都是 `CSharpSyntaxWalker`/`VisualBasicSyntaxWalker` 的子类。

**全局符号表 `globals`** 是一个 **per-project** 的 `Dictionary<ISymbol, ScipSymbol>`，跨 document 复用——同一个 project 内引用同一个 `ISymbol` 时只算一次符号字符串生成。`SymbolEqualityComparer.Default` 是 Roslyn 推荐的 ISymbol 等价比较器，避免 `==` 默认的引用比较坑。

## 4. 节点级发射 —— `ScipDocumentIndexer.cs`

代码：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:1-379`

这一层是真正干活的"翻译器"：每碰到一个 Roslyn 的 `(ISymbol, Location, isDefinition)` 三元组，就生成一个 `Occurrence` 加进 `_doc.Occurrences`，并对定义额外加 `SymbolInformation` 加进 `_doc.Symbols`。

### 4.1 `VisitOccurrence` —— 唯一的入口方法

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:216-245
    public void VisitOccurrence(ISymbol? symbol, Location location, bool isDefinition)
    {
        if (symbol == null)
        {
            return;
        }

        var symbolRole = 0;
        if (isDefinition)
        {
            symbolRole |= (int)SymbolRole.Definition;
        }

        var scipSymbol = CreateScipSymbol(symbol).Value;
        var occurrence = new Occurrence
        {
            Symbol = scipSymbol,
            SymbolRoles = symbolRole
        };
        _doc.Occurrences.Add(occurrence);
        foreach (var range in LocationToRange(location))
        {
            occurrence.Range.Add(range);
        }

        if (!isDefinition) return;

        // Emit SymbolInformation for this definition occurrence.
        var info = new SymbolInformation { Symbol = scipSymbol };
        _doc.Symbols.Add(info);
```

注意 `SymbolRoles` 只置位 `Definition` 一个 bit。**`SymbolRole.{Import, WriteAccess, ReadAccess, Generated, Test}` scip-dotnet 全部不发**。这就是为什么 011 文档里讲 CGC 必须自己用"看 reference 后面下一个字符是不是 `(`"来从 `0`(无 Definition 位) 的 reference 里筛 callsite。

### 4.2 `LocationToRange` —— Roslyn Location 转 SCIP 三/四元组

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:344-365
    private static IEnumerable<int> LocationToRange(Location location)
    {
        var span = location.GetMappedLineSpan();
        if (span.StartLinePosition.Line == span.EndLinePosition.Line)
        {
            return new[]
                {
                    span.StartLinePosition.Line,
                    span.StartLinePosition.Character,
                    span.EndLinePosition.Character
                };
        }

        return new[]
            {
                span.StartLinePosition.Line,
                span.StartLinePosition.Character,
                span.EndLinePosition.Line,
                span.EndLinePosition.Character
            };
    }
```

**单行优化**：起止同一行用三元组 `[startLine, startChar, endChar]`；跨行用四元组 `[startLine, startChar, endLine, endChar]`。SCIP 协议刻意做的紧凑编码（见 `@d:/ai-lab/scip-dotnet/scip.proto:369-388`）。所有标识符 occurrence 几乎都是单行的——所以绝大多数 `range` 是 3 元素。

`GetMappedLineSpan()` 而非 `GetLineSpan()`：这样 `#line` 预处理指令、source generator 生成的 `[GeneratedCode]` 文件都能映射回原始用户文件位置。

关系发射的两个分支：

| 当前定义符号 | 发射的 Relationships |
| :--- | :--- |
| **`INamedTypeSymbol`**（class/struct/interface/enum/delegate） | ① 沿 `BaseType` 链向上每一级（直到遇到 `System.Object/Enum/ValueType` 截断）；② 所有直接+间接接口 (`AllInterfaces`)。全部 `IsImplementation=true`。 |
| **`IMethodSymbol`** | ① `OverriddenMethod` 链；② 通过 `InterfaceImplementations()` 静态方法找到的所有显式+隐式实现的接口方法。**两类都同时设置 `IsImplementation=true` 且 `IsReference=true`**。 |

**为什么 `Object/Enum/ValueType` 要被忽略**：

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:202-214
    private readonly string[] _isIgnoredRelationshipSymbol =
    {
        " System/Object#",
        " System/Enum#",
        " System/ValueType#",
    };

    // Returns true if this symbol should not be emitted as a SymbolInformation relationship symbol.
    // The reason we ignore these symbols is because they appear automatically for a large number of
    // symbols putting pressure on our backend to index the inverted index. It's not particularly useful anyways
    // to query all the implementations of something like System/Object#.
```

每个 class 都继承 `Object`、每个 enum 都"继承" `Enum`、每个 struct 都"继承" `ValueType`，全发出来会爆炸性放大反向索引。**这是 Sourcegraph 后端定的优化**——CGC 当作普通"无父类"处理，对图谱质量没影响。

**接口实现的双向关系**：方法层用 `IsImplementation=true, IsReference=true` 双标志，对应 SCIP 协议设计里用于"Find references on the interface method should also include implementations"。CGC **只读 IsImplementation**（011 §2.1 末），不利用 `IsReference` 这个反向信号。

### 4.5 `InterfaceImplementations` —— 隐式实现也得抓

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:329-342
    private static IEnumerable<ISymbol> InterfaceImplementations(IMethodSymbol symbol)
    {
        foreach (var interfaceSymbol in symbol.ContainingType.AllInterfaces)
        {
            foreach (var interfaceMember in interfaceSymbol.GetMembers())
            {
                var implementation = symbol.ContainingType.FindImplementationForInterfaceMember(interfaceMember);
                if (implementation != null && symbol.Equals(implementation, SymbolEqualityComparer.Default))
                {
                    yield return interfaceMember;
                }
            }
        }
    }
```

Roslyn 的 `IMethodSymbol.ExplicitInterfaceImplementations` 只覆盖 `void IFoo.Bar()` 这种**显式**实现。C# 里更常见的是隐式实现（`public void Bar()` 配合接口里的 `void Bar()`）。这段代码用 `FindImplementationForInterfaceMember` **反向搜**：对每个接口成员问"谁在实现它？"——如果实现就是当前方法本身，那 `interfaceMember` 就是当前方法的接口约定。O(全部接口成员数)，但一般接口很小所以可接受。

## 5. 符号字符串生成 —— `ScipSymbol.cs`

代码：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipSymbol.cs:1-67`

`ScipSymbol` 是个**只读** wrapper，只有一个字段 `Value`（最终的字符串）。它存在的全部意义就是把 SCIP 符号字符串的拼接逻辑从字符串处理里提出来。

### 5.1 SCIP 符号语法

回顾 SCIP 协议定义（`@d:/ai-lab/scip-dotnet/scip.proto:104-126`）：

```
<symbol>     ::= <scheme> ' ' <package> ' ' (<descriptor>)+ | 'local ' <local-id>
<package>    ::= <manager> ' ' <package-name> ' ' <version>
<descriptor> ::= <namespace> | <type> | <term> | <method> | <type-parameter> | <parameter> | <meta>
<namespace>  ::= <name> '/'
<type>       ::= <name> '#'
<term>       ::= <name> '.'
<method>     ::= <name> '(' <method-disambiguator> ').'
<parameter>  ::= '(' <name> ')'
<type-parameter> ::= '[' <name> ']'
```

scip-dotnet 把 Roslyn 的 `SymbolKind` 映射到上述 7 种 descriptor 后缀：

| Roslyn SymbolKind | SCIP Descriptor 后缀 |
| :--- | :--- |
| `Namespace` | `Package` (`/`) |
| `NamedType` / `FunctionPointerType` / `ErrorType` / `PointerType` / `ArrayType` / `DynamicType` / `Alias` / `Event` | `Type` (`#`) |
| `Property` / `Field` / `Assembly` / `Label` / `NetModule` / `RangeVariable` / `Preprocessing` / `Discard` | `Term` (`.`) |
| `Method` | `Method` (`(<disambig>).`) |
| `Parameter` | `Parameter` (`(name)`) |
| `TypeParameter` | `TypeParameter` (`[name]`) |
| `Local` | `Local` |

代码：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:140-176`。

注意 **`Event` 被归为 Type 而不是 Term**：snapshot 里 `event EventHandler<int> SomeEvent` 的符号是 `Main/Interfaces#IEvent#SomeEvent#` —— 用 `#` 后缀（见 `@d:/ai-lab/scip-dotnet/snapshots/output-net8.0/syntax/Main/Interfaces.cs:78`）。这是一个让 CGC 的"`#` → Class"启发式产生**误判**的来源——Event 在 CGC 里会被当作 Class 入图。

### 5.2 递归构造法

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:70-105
    private ScipSymbol CreateScipSymbol(ISymbol? sym)
    {
        if (sym == null)
        {
            return ScipSymbol.Empty;
        }

        var fromCache = _globals.GetValueOrDefault(sym, ScipSymbol.Empty);
        if (fromCache != ScipSymbol.Empty)
        {
            return fromCache;
        }

        if (IsLocalSymbol(sym))
        {
            return CreateLocalScipSymbol(sym);
        }

        var owner = sym.Kind == SymbolKind.Namespace
            ? CreateScipPackageSymbol(sym)
            : CreateScipSymbol(sym.ContainingSymbol);

        if (owner.IsLocal())
        {
            return CreateLocalScipSymbol(sym);
        }

        var result = ScipSymbol.Global(owner, new SymbolDescriptor
        {
            Name = sym.Name,
            Suffix = SymbolSuffix(sym),
            Disambiguator = MethodDisambiguator(sym)
        });
        _globals.TryAdd(sym, result);
        return result;
    }
```

算法：

1. **缓存命中** → 直接返回（按 ISymbol 哈希）。
2. **判定为 local** → 用单调递增计数器生成 `local 0` / `local 1` / …，**不入全局缓存**（local 计数器 `_localCounter` 是 per-document 的）。
3. **递归到 ContainingSymbol**：namespace 是终止符（落到 package 描述符），其它一路向上。
4. 如果递归回来 **owner 已经是 local**（如 lambda 里的字段），整体也降级为 local。
5. 否则拼 `<owner><name><suffix>` 并入全局缓存。

> **Local 判定**：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:367-377`，命中条件是 `Local` / `RangeVariable` / `TypeParameter` / `LocalFunction`，或者匿名类（名为空字符串且不是全局 namespace）。

### 5.3 包描述符 —— `--allow-global-symbol-definitions` 的影响

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:120-138

```


### 5.4 名字转义

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipSymbol.cs:50-66

    {

        {
```

`` `.ctor` `` 被反引号包了。这与 ECMA-335 元数据里的特殊方法名（`.ctor` / `.cctor`）一致，CGC 的 `_name_from_symbol` 用 `re.sub(r"^`([^`]+)`$", r"\1", name)` 把这层反引号扒掉（011 §3.2）。

### 5.5 方法 disambiguator

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:178-200
    private static string MethodDisambiguator(ISymbol sym)
    {
        if (sym is not IMethodSymbol)
        {
            return "";
        }

        var overloadCount = 0;
        foreach (var member in sym.ContainingType.GetMembers())
        {
            if (member.Equals(sym, SymbolEqualityComparer.Default))
            {
                return overloadCount == 0 ? "" : $"+{overloadCount}";
            }

            if (member.Name.Equals(sym.Name))
            {
                overloadCount++;
            }
        }

        return "";
    }
```

C# 重载方法（同名不同签名）需要在 `<name>(<disambig>).` 里塞一个区分符。算法：枚举 `ContainingType` 的所有成员，按出现顺序数同名方法，第 0 个空串、第 1 个 `+1`、第 2 个 `+2`……

snapshot（`@d:/ai-lab/scip-dotnet/snapshots/output-net8.0/syntax/Main/Classes.cs:26,36`）：

```
//           ^^^^^^^ definition scip-dotnet nuget . . Main/Classes#`.ctor`().      ← 第一个 ctor
//           ^^^^^^^ definition scip-dotnet nuget . . Main/Classes#`.ctor`(+1).    ← 第二个 ctor
```

`Console.WriteLine` 那种重载多达 18 个的 `WriteLine(+7)` / `WriteLine(+9)` / `WriteLine(+11)` 都是同一个原理。

> **稳定性问题**：disambiguator 依赖 `GetMembers()` 的**顺序**。Roslyn 对源码定义顺序是稳定的，但对从 metadata 反射出来的成员（如 `System.Console`）顺序由 metadata 表决定——只要 .NET runtime 版本不变就是稳定的。换 SDK 版本可能改变 disambiguator——这是 snapshot 测试要按 net6/7/8/9/10 分目录的核心原因。

### 5.6 Local 符号

```@d:/ai-lab/scip-dotnet/ScipDotnet/ScipDocumentIndexer.cs:107-118
    private ScipSymbol CreateLocalScipSymbol(ISymbol sym)
    {
        var local = _locals.GetValueOrDefault(sym, ScipSymbol.Empty);
        if (local != ScipSymbol.Empty)
```

### 6.2 VB 走查器的差异

代码：`@d:/ai-lab/scip-dotnet/ScipDotnet/ScipVisualBasicSyntaxWalker.cs:1-144`

## 9. 关键设计取舍

| 决策 | 利 | 弊 |
| :--- | :--- | :--- |
| **完全外包给 Roslyn**（不自己 lex/parse） | 准确率上限就是 C# 编译器；任何 C# 新语法 Roslyn 升级即支持 | 对 binding 失败（缺包、缺 `dotnet restore`）零容错；MSBuild 启动慢 |
| **MSBuildWorkspace 单例 + DI 主机** | 跨 csproj 复用编译缓存；优雅集成 logging | 进程内只能一次索引；workspace 的 fail-and-continue 行为掩盖错误 |
| **同步走查 + 累积 Index**（非流式） | 实现简单、内存里就能做后处理 | 大仓库 `Index.ToByteArray()` 内存峰值高 |
| **`IndexLocalPackage` 默认开启** | 防止源码符号污染全局 NuGet 命名空间 | 同一份源码在不同仓库出现就会被当作不同符号；跨仓库 Find Refs 失效 |
| **不发 SymbolInformation.kind / display_name / enclosing_range** | scip-dotnet 用的旧版 scip.proto 没这些字段，迁移成本高 | 下游消费者（如 CGC）必须用启发式补；丢失精度 |
| **不发 SymbolRole 的 ReadAccess/WriteAccess/Import** | 字段简单、文件小 | 下游想做"找写操作"只能源码级文本判断 |
| **多目标框架靠当前 runtime 版本去重** | 实现极简（一行 LINQ） | 脆弱——跑在错误的 runtime 上会丢符号或重复索引 |

## 11. 一句话总结

`scip-dotnet` 的本质是：**用 Roslyn 拿到 `(ISymbol, Location, isDefinition)`，把 ISymbol 沿 `ContainingSymbol` 链格式化成 SCIP 符号字符串，对每个定义补上签名+XML 文档+继承/接口/override 关系，全部塞进一个 `Index` 拍成 protobuf**。它有意识地把所有"语言理解"留给 Roslyn，自己只做"两个数据模型的翻译"——这种克制让整个仓库不到 1000 行 C# 就实现了一个生产级的 C#/VB 语义索引器。

CGC 消费这个产物的方式见 `@d:/ai-lab/CodeGraphContext/ai-context/docs/011.CodeGraphContext-Uses-of-scip-dotnet.md`。
